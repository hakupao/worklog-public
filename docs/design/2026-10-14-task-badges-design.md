# 案件徽章（task badges）设计

2026-10-14 · 与用户 brainstorm 定稿（会话内逐段确认，原型见 `docs/design/prototypes/2026-10-14-badges/`）

> **G0 第 1 轮修订（2026-10-14）**：用户在调参原型 `badge-g0-tune.html` 里拍板后改了 D2、D7、§2.1、§2.3、§2.4、§4 的数值和规则（比例 3.2、S/M 主角不再放大裁切、里背景加深去色并取消描边隔离、表颗粒 0.4、物件库加 Fluent Emoji 高对比）。实施计划：`docs/plans/2026-10-14-badges-b0-g0-round1.md`。下文已是修订后的内容。

## 1. 目的

案件编号（`T20261001-01` → 界面显示 `1001-01`）换成**每个案件一枚、随机生成、好看好玩的徽章**：

- 一眼认出是哪个案件（小尺寸下也要认得出），不用读编号；
- 有质感、有特征，带物件（动物、交通工具……）和随机元素；
- 除案件页 / 案件抽屉外，全站不再显示编号。

副目标：用户借这个项目训练产品审美和设计思维 —— 每个取舍要讲清「为什么」。

### 用户原话与决定

| # | 问题 | 决定 |
|---|------|------|
| D1 | 徽章的作用 | 取代编号的位置和作用：一眼知道是什么案件 + 有特征好看；只有案件页还需要编号 |
| D2 | 外形 | 超椭圆胶囊（两头是超椭圆 n≈4.2，侧边更平），比例 3.2 : 1（G0 第 1 轮由约 1.9 : 1 加长） |
| D3 | 内部 | 要填满；小尺寸要看得清 |

## 2. 徽章语言

一枚徽章由下面几层组成，**只有物件和颜色存库，其余全部由 ID 确定性算出**（同一个 ID 在任何地方画出来都一样）：

| 层 | 来源 | 说明 |
|----|------|------|
| 颜色 | D1 列 `badge_color` | 调色板序号；同时是时间线等处的 `lineColor` |
| 物件（主角） | D1 列 `badge_obj` | 物件库里的名字，格式 `来源:名字`（如 `phosphor:cat`、`fluent:panda`；两库都有 cat） |
| 朝向 / 主角水平位置 | ID 种子 | 左右翻转、位置 |
| 景观类型与地形 | ID 种子 | 约 8 种（§2.2），地形起伏、楼高、亮哪几扇窗 |
| 季节天气 | ID 里的日期 | 月份 → 春樱 / 夏萤 / 秋枫 / 冬雪；日 → 数量 |

种子：`fnv1a(task_id)` 驱动的确定性 PRNG（原型里的 `rng(fnv(id+"scene"))`）。

### 2.1 外形与边框

- 外形：超椭圆胶囊，viewBox `320 × 100`（比例 3.2，G0 第 1 轮），`|x/a|^4.2 + |y/b|^4.2 = 1`。
- 边框：**钻石切边**（diamond-cut bevel）——多段亮带的线性渐变 + 6 道细车纹（tool marks）发丝线 + 内侧一道亮边、一道暗台阶。表、里两个世界都用，颜色取徽章色。

### 2.2 景观（C）与日本风景剪影（D9）

现有 3 种（山野 / 城市夜景 / 海上日出）+ 新增自绘日本风景剪影约 10 个（富士山、城郭、五重塔、东京塔、跨海大桥、海上鸟居、鸟居 + 稻田、竹林……），组合成约 8 种景观，例：山野（远景富士山）、城下町（城郭 / 五重塔）、港町（东京塔 / 大桥）、海（海上鸟居）、乡间（鸟居 + 稻田）、城市夜景、海上日出、竹林。剪影只用在远景层，细节要求低。

### 2.3 尺寸分层（LOD）

原则：**每个尺寸只回答一个问题**——小尺寸只回答「这是哪个案件」，大尺寸才讲「这个案件的故事」。

| 档 | 显示高度 | 内容 | 点阵点距（里） |
|----|---------|------|---------------|
| S | ≤ 24px | 只有主角（物件框 100 单位高、从 y = 0 起；G0 第 1 轮前是放大 138% 裁切。**B2 G2 后（2026-10-14，用户定）：S / M 主角固定在右侧，物件框右沿 x = 265**——随机位置让一列徽章左右乱跳；265 是裁切墨迹与居中基本相同的最右位置（197 个物件平均 1.14 %，居中 1.04 %，都来自上下边）。原为按 id 种子左右滑动，两端最坏裁掉约 18 %。100 单位高时上下边仍可能蹭到场边） | 9.5 |
| M | 25–48px | 主角同上 + 一层剪影远景 | 6.5 |
| L | > 48px | 完整景观（远景 + 近景 + 天空）+ 季节天气 + 主角（96 单位高，站在 y = 98；仍按 id 种子左右滑动——L 单独出现，不用对齐） | 5 |

表世界在主角外围描一圈底色（描边隔离，knockout）。里世界不再熄灭主角周围的点（G0 第 1 轮：隔离宽度 0），改由景观点去色 + 主角强辉光把主角分出来（§2.4）。

### 2.4 两种材质（D5）

- **里（④ 满屏点阵）**：暗玻璃底（`#06080a` 向徽章色混 10%）+ 四档亮度的灯珠——主角全亮、纯徽章色、强辉光（模糊 3、强度 ×2），近景 1、远景 0.6、熄灭 0.2；景观三档的点用徽章色向灰（`#8c939c`）混 60%（G0 第 1 轮：原为近景 0.6、远景 0.26、熄灭 0.07、不去色）。**S 档例外（B2 G2 后，2026-10-14，用户选方案 C）**：底色向徽章色混 25%、熄灭点 0.35——18–24px 放在手机深色卡片上时，原底色看起来是空的；M / L 档不变。
- **表（① 冲压做旧）**：暗色徽章色底 + 喷砂颗粒（强度 0.4，G0 第 1 轮）；景观和主角是冲压浮雕（光照滤镜 + 下沉阴影），远景浮雕透明度 0.42、近景 0.75。**只有 L 档用光照滤镜**；S / M 档用预制的渐变 + 阴影简化版（小尺寸下滤镜效果看不出来，且最耗性能）。表世界是浅色纸面（`#f4f5f7`），徽章在浅底上的效果在 B0 实验页确认。

### 2.5 徽章语言的分级（D8、D10）

徽章由四个元素组成：**色**（分配色）、**形**（超椭圆胶囊）、**质**（里 = 点阵，表 = 钻石切边 + 喷砂）、**物**（物件剪影）。图表里看不到徽章，只要用上其中两三样，视觉上仍是同一家族。每个位置按「放得下什么」从高往低选：

| 级 | 表达 | 典型位置 |
|----|------|---------|
| 1 | 完整徽章（按 §2.3 选档） | 列表行、抽屉、此刻页、计划芯片、tooltip |
| 2 | 单色物件剪影（无框、无景观） | 图表数据标签、图例 |
| 3 | 色 + 形 + 质：胶囊形色块 / 行首胶囊色条 / 低浓度底色；里世界大色块用点阵纹理，表世界边缘加细亮边 | 表格行、格子、柱子、色带、区块 |
| 4 | 仅颜色 | 细线、小柱子等纹理会干扰读数的地方 |

约束：
- 底色要克制：低浓度（约 8–12%）或只用行首色条，不整行涂满。
- 纹理只用在大面积色块上，细线 / 小柱子只用颜色。
- 只靠颜色会撞色：凡是级 3 / 4 的位置，悬停 tooltip 里放完整徽章兜底。

## 3. 数据与分配（D6）

- 迁移 `0019`（0018 已被手机版 harvest_runs 占用）：`tasks` 加 `badge_obj TEXT`、`badge_color INTEGER`（可空，旧客户端不受影响）。
- `POST /api/tasks` 分配：
  1. 物件：优先选**所有 `open` / `hold` 案件都没在用**的物件；都用过时选使用次数最少的；平手按 ID 种子挑。
  2. 颜色：在 `open` / `hold` 案件里使用次数最少的颜色；平手按 ID 种子挑。
- `wl new` 走同一个接口，CLI 不改。
- 老案件：不另跑脚本、不设 cron——服务端 `assignMissingBadges` 在每次 `GET /api/tasks`（网页进站、每小时 harvest 都会读）时，把 `badge_obj` 为空的案件按 `received_at`、ID 升序用同一套规则补上，每次最多 20 条（不论 `?status` 过滤，补的是任意空行）；每次 POST / PUT 之后另补刚写入的那条（最多 3 条）。D1 每次调用 50 条查询的上限：补 20 条时 GET 共 24 条（带 X-Lang 时 25 条），无需补时 2–3 条。补失败只记日志，不让请求失败。没有 cron：Cloudflare 从未触发第三个触发器，见 `failures/b1_deploy_attempt_2.md`。读写同时补同一行时先写者生效，最坏结果是一处颜色或物件重复，可接受。
- 删除案件 → 徽章自然释放；ID 复用时新案件重新分配，不继承旧徽章。
- PUT（CLI 整行回写）不碰这两列；PATCH 不接受这两列（不可手动改，§6）。被剔除的物件名留在库里，前端退回兜底，分配时不计入占用。
- `GET` 返回案件的地方都带上这两个字段。
- 前端 `lineColor(id)`：优先读已加载案件的 `badge_color`，查不到退回现在的哈希色。全站 44 个调用文件颜色随之统一；表世界的 `inkOf()` 照旧在它基础上加深。（实现：`web/src/v2/ui/taskBadges.ts` 登记表，API 客户端在每个带案件行的响应里登记；V2App 进站时取一次全量案件列表。）
- 调色板：沿用 `LINE_PALETTE` 12 色；表世界对比度在 B0 实验页确认。

## 4. 渲染与性能

- 模块放在 `web/src/v2/badge/`：物件库、场景生成（纯函数，可单测）、两个渲染器、LOD 选择、缓存，对外只暴露 `<Badge task={…} size={…} />` 和一个取位图 URL 的函数（给图表用）。
- 渲染：SVG 串 → `Image` → `canvas` → 位图，按 `(task_id, 档, 世界, devicePixelRatio)` 缓存，**同一组合全页只渲染一次**。照顾 Win11 弱机。
- 世界切换（`data-world`）时按新世界取缓存或重画。
- 物件库：Phosphor fill + Fluent Emoji 高对比的子集打包进前端（生成脚本只带选中的路径，Fluent 压成单一路径、缩放进 256 框，个别物件用 even-odd 填充；不引整个图标包）；两库许可（MIT）记录在 `web/src/v2/badge/NOTICE.md`。剔除名单在 `culled.ts`，存库的物件名被剔除后按未分配处理（退回 ID 哈希挑选）。
