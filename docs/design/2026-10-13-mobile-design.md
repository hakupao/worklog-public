# 手机版 设计书

> 给 worklog 加一套手机专用界面。桌面 v2（表 / 里世界、LED 信息牌）不适合手机显示，也不改它；手机版是同一个网站里另一套轻量界面，共用数据层。

## 1. 目的与成功标准

用户在手机上要做的四件事（10/13 用户选定）：
1. **瞥一眼现在**：正在跑什么、今天干了多久、今日安排进度。
2. **轻量操作**：只有**每日计划**可编辑（勾选完成、新增、改文字和具体目标、删除；可以给明天写安排）。其余全部只读。
3. **回看查询**：翻某一天的 session、看某个案件的详情。
4. **给别人看**：当面展示时间和数字，token / 费用正常显示。

成功标准（用户原话：「一定要交互好，显示没有 bug，不会造成撑爆容器的情况」）：
- 360–430px 宽的任何页面、任何弹出面板，页面都不出现横向滚动，没有文字溢出容器。
- 所有可点区域不小于 44×44px；所有信息都能直接看到或点开看，不依赖悬停。
- 手机上做的计划修改，桌面端刷新后立刻可见，反过来也一样。

不做（10/13 用户确认放弃）：表 / 里世界与 LED 信息牌、統計的 24 个视图、週報（编辑、导出、润色，以及週報页本身）、设置页、预判下一步、桌面的动效选项、session 关联 / 改摘要 / 隐藏、案件编辑。

来源：
- 讲解页 `docs/design/prototypes/2026-10-13/mobile-options.html`（三种实现方式，用户选方案 1）。
- 可点原型 `docs/design/prototypes/2026-10-13/mobile-proto.html`（示例数据；用户确认结构与交互方向，视觉选 A 作深色、B 作浅色）。

## 2. 已定决策

| # | 决策 |
|---|---|
| M1 | 方案 1：同一 SPA 内新增手机外壳 `#/m/*`，懒加载，独立 CSS；数据层复用；桌面代码不改（入口跳转那几行除外） |
| M2 | 5 个标签：此刻 / 时间线 / 案件 / 计划 / 统计；不做週報，周总时长并入统计 |
| M3 | 只有每日计划可写；其余只读，只读面板里注明「在桌面版操作」 |
| M4 | 计划编辑 = 勾选完成（手动状态）、新增、改文字、写「具体目标」（`detail`）、改手动状态（按 AI / 完成 / 部分 / 未做）、删除；可以切到其他日期，包括未来日期（「开始安排明天」） |
| M5 | token / 费用正常显示，不做隐藏开关 |
| M6 | 明暗两套：深色 = 原型 A「里·轻」（点阵数字 + 琥珀辉光、细线分区、不用圆角卡片），浅色 = 原型 B「玻璃」（磨砂层 + 柔和光斑）；默认跟随系统，可以手动切换 |
| M7 | 「AI 味」较重的个别元素留到第 4 阶段集中做视觉打磨；前 3 阶段只保证结构、交互和稳定性 |

## 3. 路由与入口

- 路由：`#/m/now`、`#/m/tl[/YYYY-MM-DD]`、`#/m/tasks[/taskId]`、`#/m/plan[/YYYY-MM-DD]`、`#/m/stats[?range=today|week|month]`。地址不合法时回退到该标签的默认值（今天 / 列表 / 本周），不抛异常，沿用 `parseV2Route` 的做法。
- `App.tsx` 增加 `isMobileHash`，命中时懒加载 `MobileApp`；桌面端不加载手机代码。
- **自动跳转**：`matchMedia("(max-width: 700px)")` 命中，且本机没有「用桌面版」标记时，打开 `#/v2/<page>`、`#/` 或 v1 页面会用 `replaceHash` 换成对应的 `#/m/<page>`。对应关系：now→now，timeline→tl，tasks→tasks，plan→plan，stats→stats；report / usage / settings → now。
- **「桌面版」入口**：顶栏菜单里的一项，点了在 localStorage 写 `wl-mobile=off`（读写都包 try/catch），然后跳到 `#/v2/now`。桌面版的 Dock 在窄屏时显示「手机版」入口，点了清除标记。
- 不改 Cloudflare Access 和 Worker：同一网址、同一登录。

## 4. 代码组织

```
web/src/m/
  MobileApp.tsx        外壳：路由、主题、语言、顶栏、标签栏、Toast
  route.ts             解析与生成 #/m/*，以及与 #/v2/* 的对应关系
  theme.ts             明 / 暗：跟随系统 + 手动覆盖（prefs 里加 mobileTheme: "system"|"dark"|"light"）
  ui/Sheet.tsx         底部弹出面板（拖拽关闭、Esc、焦点归还、滚动锁定）
  ui/TabBar.tsx        浮动标签栏 + 滑块指示
  ui/DayNav.tsx        ‹ 日期 › + 左右滑动
  ui/Num.tsx           数字（深色用点阵字体）+ 从 0 滚动的动画
  ui/State.tsx         骨架 / 出错（重新载入）/ 空状态，三种统一组件
  pages/Now.tsx  Timeline.tsx  Tasks.tsx  Plan.tsx  Stats.tsx
  styles/m.css         手机唯一的样式文件；token 在 :root[data-m-theme]
```

- **数据**：只用现有 hook 和 `api/queries` 的 query key，不新增后端接口。
  - 此刻：`useNowData` 里实际用到的那几个 query（timeline 当周、未关联、今日 day plan、machines）。
  - 时间线：`useTimeline(week)`，按天取 `days[]`，显示 `minutes_on_day`。
  - 案件：`useTasks` + `useTaskTotals`，详情用 `useTask(id)`。
  - 计划：`useDayPlan(date)`；写入复用 `v2/pages/plan/write.ts` 的 `usePlanQueue`。它依赖 `useV2()` 的 `lang`，所以 `MobileApp` 用 `usePrefs()` 提供一个真实的 `V2Context`（prefs、lang、setPrefs、resetPrefs、setLang）。`write.ts` 从 `timeline/SessionDrawer.tsx` 引入了 `reportWriteError`，会把桌面抽屉连带打包进来：要把 `reportWriteError` 移到一个不依赖界面的共享文件（例如 `v2/pages/writeError.ts`），桌面两处引用一起改掉。
  - 统计：工作时间和每日柱状图来自 timeline 的 `wall_minutes`（今天 / 本周取当周，本月取覆盖当月的各周，按日期过滤）；累计耗时、token、费用、按案件排行来自 `useDashboard(from,to)` 的 `overview` 和 `time.by_task`。口径与桌面 週報 / 统计一致：一天按 0 点切分。
- **文案**：沿用 `v2/i18n`（中 / 日 / 英），新增词条加 `m.` 前缀。语言跟随 prefs，顶栏可以切换。
- **字体**：深色的点阵数字用 Google Fonts「Doto」（只用于数字和拉丁字母，带等宽回退字体）；CJK 用系统字体。不加载 LED 点阵字体。
- **禁止引用**：`v2/led/*`、`v2/world/*`、`v2/ink/*`、ECharts、`v2/styles/v2.css`。

## 5. 页面

**此刻**
1. 运行中：每个运行中的 session 一行（频谱条动画、案件名、摘要两行、时长、机器）。没有时显示一行说明。
2. 今日「工作时间 / 累计耗时」两个大数字（用户要求两个数字一起显示）。
3. 今日安排：完成进度环 + 条目（与计划页同一个行组件，可以勾选）+「全部 ›」跳到计划页。
4. 今天：未关联条数（点了跳到时间线并只看未关联）、各机器最后采集时间（超过 2 小时标黄）。
- 每 5 分钟刷新一次（沿用 `REFRESH_MS`），切回前台时也刷新一次。

**时间线**：DayNav（‹ › 和左右滑动，不能翻到今天以后）、「全部 / 只看未关联」、session 行（开始时间、案件名、摘要两行、时长）。点一行弹出只读面板：时间段、耗时、机器和 agent、摘要、所属案件（点了跳到案件详情）。

**案件**：搜索（案件名 / 依頼元，只在本地过滤）、状态筛选（对应中 / 保留 / 完了 / 全部，默认对应中）、行内显示案件名、依頼元、最近日期、累计时长和比例条。点一行弹出详情面板：依頼元、状态、累计、最近 10 条 session、成果物（只读）。

**计划**：DayNav（往前不限，往后最多到 +7 天）。当天还没开始时，显示「开始安排<日期>」按钮（`startDayPlan`）。
- 条目行：左边状态方块，点了在「完成」和「未做」之间切换，写的是 `manual_status`；右边是文字和目标或 AI 说明，点了打开编辑面板。
- 编辑面板：内容、具体目标、状态四选一（按 AI / 完成 / 部分 / 未做，「按 AI」= `manual_status:null`）、AI 判定说明（只读）、删除（第一次点变成「再点一次删除」，第二次才执行，不用系统确认框）。
- 底部输入框新增条目，回车也可以提交，提交后焦点留在输入框。
- 新增的条目一律是当天的自由文字条目（`addDayPlanItem` 只传 `text`）。从周期计划拉进来、给条目挂案件，都留在桌面端。

**统计**：今天 / 本周 / 本月三档。四个数字：工作时间、累计耗时、token、费用（`cost_partial` 时数字后面加 `+`，并加注）。每天工作时间的柱状图（本周和本月有，今天没有；本月按日期画，横向不滚动，柱子宽度自适应）。按案件前 5 名（剩下的合并成「其他」），session 数量。

## 6. 交互与动效

- 底部标签栏浮动，滑块用弹性动画滑到当前标签；切换标签时内容淡入并上移 8px。
- 时间线和计划的日期可以左右滑动切换：水平位移大于 60px 且大于垂直位移的 1.5 倍才算；内容朝滑动方向进出；滑到边界时不动。
- 数字只在进入页面、切换统计范围时从 0 滚动到实际值，数据刷新时不重播。条形图和柱状图在同样的时机逐个长出来。
- 计划勾选：方块回弹，对勾是画出来的，手机支持时轻震 10ms（`navigator.vibrate`，不支持的系统里直接跳过）。
- 弹出面板：从底部弹出，按住顶部往下拖超过 90px 关闭，点遮罩或按 Esc 也能关闭；打开时锁住背景滚动，关闭后把焦点还给原来的按钮。
- `prefers-reduced-motion` 打开时，以上所有动画都不播。
- 原型里的「风格切换栏」不进正式版。

## 7. 防撑爆规范

写进 `m.css` 的开头注释，评审时逐条对照：
1. 整页单列，`max-width:440px`，左右各留 16px 边距；不设任何比屏幕宽的 `min-width`。
2. 所有 flex / grid 的子元素，只要里面有文字，一律 `min-width:0`。
3. 标题单行省略（`text-overflow:ellipsis`），摘要最多两行（`line-clamp:2` + `overflow-wrap:anywhere`），面板里的长文本完整换行显示。
4. 数字区用 `white-space:nowrap` + 等宽数字，并限制最大字号，保证 360px 宽、两列时放得下 `999:59` 和 `$9999.99+`。
5. 只有筛选标签那一行允许在自己的容器里横向滚动，页面本身永远不横向滚动。
6. 顶栏和标签栏处理 `env(safe-area-inset-*)`；页面底部留出标签栏的高度，内容不会被挡住。
7. 输入框字号不小于 16px，避免 iOS 聚焦时自动放大页面。

## 8. 出错与边界

- 加载中显示骨架（和最终内容同样的行高，避免跳动）；接口失败显示原因和「重新载入」按钮；没有数据时给出明确的空状态说明（例如「这一天没有记录」「还没有安排，在下面加第一条」）。
- 计划写入：`usePlanQueue` 保证按顺序执行；遇到 409 冲突时用 Toast 提示「已被别处修改，已刷新」，并重新拉取数据；编辑面板保留用户输入的草稿，不清空。
- 网络断开时，写入按钮仍然可点，但失败后提示原因，不做离线队列。
- 采集不及时（最后采集超过 2 小时）只是标黄，不报错。

## 9. 测试

- **vitest**：`m/route.ts` 的解析和生成、与 v2 路由的对应关系、自动跳转的判断（宽度 × 「用桌面版」标记 × 原地址）、DayNav 的边界、统计范围的日期计算（本月跨周）。
- **Playwright**（沿用仓库里的 playwright-core + 本机 Chrome）：
  - 在 360、390、430 三个宽度下，打开每个页面和每种弹出面板，断言 `document.documentElement.scrollWidth <= innerWidth`，并检查所有 `.t1` / `.t2` 的内容不超出容器。
  - 压力数据：80 字的案件名、500 字的摘要、0 条和 60 条 session、`$12345.67` 的费用、跨午夜的 session。
  - 计划流程：开始明天的安排 → 新增 → 改文字和目标 → 改状态 → 勾选 → 删除；以及模拟 409 冲突。
  - 深色和浅色主题各跑一遍截图，留存到 evidence 目录。
- **真机验收**：iPhone Safari 由用户自己点（滑动、拖拽、输入框聚焦、安全区域），结果记录在验收清单里。

## 10. 分阶段

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| 1 | 外壳、路由、自动跳转和桌面版入口、主题、标签栏、Sheet、State 组件；此刻 + 时间线 | 宽度测试通过；真机能瞥一眼和翻日期 |
| 2 | 计划（全部编辑流程） | 计划流程测试和 409 测试通过；真机能改明天的计划 |
| 3 | 案件 + 统计 | 全部页面的宽度测试通过；线上验收 |
| 4 | 视觉打磨：去掉「AI 味」元素，单独做一轮设计评审 | 用户确认 |

每个阶段单独提交并上线；第 4 阶段开始前另外讨论具体的打磨方向。
