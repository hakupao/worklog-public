# 统计可视化扩展 设计书（子项目 7b）

> 界面重设计子项目 7b。总设计书 `2026-10-05-ui-redesign-design.md` 的补充：只写统计页可视化扩展新增和不同的地方，视觉系统、表 / 里、三语、测试约定都沿用总设计书。

## 1. 目的

统计页不复刻旧首页的图表，而是把自己的工作数据做成最好看、最炫的可视化，回馈工作习惯（作息、并行与专注、投入产出与成本、计划兑现）。用户：「一切数据都有意义，后期想看什么再提；现在要好看、要灵感」。所以页面放很多视图，每个都能在设置里关掉、排序。

来源：
- 视图实验室原型 `.superpowers/brainstorm/8687-1791173322/content/page-stats-lab.html`（18 个视图，线上真实数据，本地不入库），笔记 `docs/projects/2026-10-05-ui-redesign/evidence/sub7b/lab_notes.md`。
- ECharts 主题试验 `page-stats-echarts.html`，笔记 `evidence/sub7b/echarts_notes.md`。
- 用户裁定 U10–U20（`evidence/sub7/rulings.md`）。

## 3. 页面结构

从上到下：
1. **控制行 + 指标条 + 提示**（子项目 7，固定在顶部，不可关闭；指标条标注「累计」）。
2. **视图区**：按用户的顺序排列开着的视图，每个视图是信息牌上的一个分区（细线分隔，不用卡片），头部是编号 + 名字 + 一行「它揭示什么」+ 右侧的关键数字。
3. 每个视图只在滚到视口附近时才计算和绘制（`IntersectionObserver`），之后缓存；切区间 / 切世界时只重画已经画过的。

视图跟随页面区间（今天 / 本周 / 本月 / 近 4 周 / 近 3 个月 + ◀ ▶）。按周的视图（案件时间流、日历）显示与区间相交的周，被截断的周标出。区间太短、数据不够时视图显示一行暗字说明（例如「今天」时作息瀑布只有一行）。

## 5. 数据

### 5.1 新接口 `GET /api/stats/sessions?from=YYYY-MM-DD&to=YYYY-MM-DD`

只读。区间校验与 `/api/dashboard` 相同（`parseRange`：必须成对、合法日期、from ≤ to、≤ 366 天）。返回：
- `range: {from, to}`、`day_start: "05:00"`；
- `sessions[]`：区间 [from 05:00, to+1 05:00)（JST）内有活动的、未隐藏的会话，字段精简：`id machine agent task_id started_at ended_at active_minutes turns files`（数量）`intervals`（`active_intervals`，缺失时按 `[started_at, +active_minutes]` 补，标 `approx: true`）`tokens`（按模型的 `input output cache_read cache_write` 合计）`cost_usd cost_partial summary`（前 80 字）；
- `plans[]`：区间内各天的今日安排条目 `date text task_ids ai_status manual_status`。

案件信息（标题、依頼元、项目、状态）用前端已有的 `keys.tasks`。不加迁移。

### 5.2 前端计算（纯函数，`web/src/v2/pages/stats/viz/`）

- `day.ts`：5:00 日界的日期归属、把区间切到日 / 小时格（JST）。
- `wall.ts`：墙钟并集、并行度时间线（事件扫描）、峰值；按案件平分重叠（同一时刻有 k 个案件的会话开着，每个案件得 1/k）；按机器 / agent / 依頼元同理。
- 各视图的派生函数单独成文件，输入是接口返回 + 案件表，输出是绘制用的数据；都有单元测试（含跨 5:00、跨午夜、并行、缺区间的会话）。

### 5.3 缓存与刷新

`keys.statsSessions(from, to)`，保留上一份、5 分钟刷新（同统计页其他查询）；会话 / 案件写入经 `invalidateAll` 也失效它。

## 6. 显示开关（U20）

偏好新增 `stats: { order: string[]; off: string[] }`：
- `order`：视图 id 的顺序；未知 id 丢弃，缺的 id 按默认顺序补在末尾（以后加视图时自动出现）。
- `off`：关掉的视图 id。
- web 与 server 的偏好校验 / 默认值一起改（`prefs.test` 钉住一致）。
- 设置页新增一组「统计页视图」：每个视图一行（名字 + 一行说明 + 勾选 + 上移 / 下移），「恢复默认」。
- 表世界：`stats.cost` 隐藏时 `compute`、`ai` 不渲染、其他视图里的金额不显示（星图大小改用 token、平行坐标去掉费用轴）；`stats.review` 隐藏时 `review` 不渲染。

## 7. ECharts（U19）

- 依赖 `echarts`（5.x），按需引入 `echarts/core` + `SankeyChart GraphChart ParallelChart PictorialBarChart BarChart(polar)` + 需要的组件，只在统计页用 `import()` 懒加载，进独立的 chunk；主包与 `V2App` 不增加。
- 主题两套（`viz/echarts-theme.ts`）：里 = 透明底透出点阵、3px 点图案填充、发光、像素字体轴标签、L0–L3 用透明度近似；表 = 纸面墨色、细网格、表世界字体。切世界时换主题重绘。
- 组件 `<EChart option world>`：创建 / `setOption` / 尺寸变化 / 卸载时 `dispose`；悬停案件时与全站的 `data-task` 联动（`dispatchAction` 高亮）。
- 入场动画关掉，改用本站的「打开页面」动效（整块牌面亮起）；减少动效时不动。

## 8. 视觉与交互

- 沿用信息牌语言：3px 晶格、L0–L3、颜色只表达含义（琥珀默认、线路色 = 案件、绿 = 运行中、红 = 唯一告警），没有线路色的案件走共用色板。
- 每个视图的表世界版本：实色 / 墨线、细网格、正文字体刻度。
- 悬停任一案件，全页（含 ECharts 视图）提亮该案件。
- 运动预算：每个视图最多一处在动（河流、星图各一处微动；表盘指针每分钟走一格）。
- 无障碍：画布 `aria-hidden`，每个视图有一段读屏摘要（关键数字），交互控件可用键盘。

## 9. 测试与验证

- 单元：`day.ts` / `wall.ts` 与每个派生函数（边界：5:00、午夜、并行、单会话、空区间、缺区间会话）；偏好 `stats` 的校验与补齐；`toV2Href` 等沿用。
- 组件：视图按 `order` / `off` 渲染、懒绘制、表世界叠加隐藏、ECharts 组件的创建 / 销毁 / 换主题（jsdom 下桩掉 echarts）。
- 服务端：新接口的区间校验、字段、隐藏会话排除、缺区间补齐、跨 5:00 的会话归属。
- 截图：每个视图两个世界（图片只留本地）；体积：主包、`V2App`、ECharts chunk 分别记录。
- 线上核对：数字与实验室原型（同区间）一致，墙钟总数 ≤ 累计。

## 11. 风险

- 视图多、首绘慢：懒绘制 + 缓存派生结果；近 3 个月的地形 / 平行坐标要实测。
- ECharts 质感只有约七成：只用在交互价值大的 5 种，入场动画关掉。
- 墙钟与累计并存：两种口径同页出现，必须标清（「累计」标注、头条里同时给出两者）。
- 已保存的偏好没有 `stats` 键：按默认（全开、默认顺序）处理，不需要手动勾。
