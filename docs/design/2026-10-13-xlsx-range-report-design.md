# 跨周 xlsx 报告（看板优先）设计

2026-10-13 · 与用户 brainstorm 定稿（会话内逐段确认）

## 1. 目的

xlsx 周报从「单周汇报材料」改为「跨周工作档案 + 数据看板」：

- 本周工作只**简略**说明（一句话），降低汇报占比；
- 以往每周的工作**累计**显示在同一个文件里；
- 用 **Excel 原生图表**统计关键数字和指标；
- **最重要的是好看**。

受众：内外同一份（派遣公司 / 客户 / 自己），内容按「可以对外」的标准。
打开方式：Windows 版 Excel、Mac 版 Excel（不考虑 Numbers / Google 表格）。

### 用户原话与决定

| # | 问题 | 决定 |
|---|------|------|
| D1 | 给谁看 | 不区分内外，同一份 |
| D2 | 累计范围 | 下载时自己选起止周 |
| D3 | 指标 | 每周工时趋势、案件完成情况、时间去向占比、AI 使用量（全选） |
| D4 | sheet 结构 | A 看板优先（概览 / 每周一览 / 案件一览 / 数据），去掉日别作業・成果物・稼働明细 |
| D5 | 每周说明 | 新生成一句话版 |
| D6 | 图表技术 | A 代码生成 DrawingML 图表（不用二进制模板、不用图片） |
| D7 | 视觉定稿 | 先用 prod 真实数据出 3 份风格样稿，用户在 Excel 里挑 |

## 2. 入口与文件

- 週報页 ↓xlsx → 选起止周（默认：有数据的第一周 … 当前周）+ 语言（中文 / 日本語 / EN，默认日本語）。
- 新接口 `GET /api/reports/range/xlsx?from=<YYYY-Www>&to=<YYYY-Www>&lang=ja|zh|en`。
  - `from > to`、周格式错误 → 400；范围超过 52 周 → 400（上限可在 CPU 实测后调整，见 §8）。
- 文件名 `<from>_<to>-<lang>.xlsx`；`from == to` 时仍用同一格式。
- 旧接口 `GET /api/reports/:week/:template/xlsx` 保留（旧链接 / 旧页面），網页入口改指新接口。
- **不读 `report_overrides`（手改格子）**，与 PDF 一致：手改是按周存的，在跨周汇总里含义不清。週報页面的预览与手改照旧。

## 3. sheet 结构

sheet 名、表头、标签全部走三语 labels（`server/src/report/labels.ts` 的方式）。

### ① 概览

- 顶部：标题（范围 + 生成日）与一排 KPI：**总工时**、**周均工时**、**完成案件数**、**AI 费用**。
- 4 张原生图表：
  1. 每周工时 —— 按依頼元堆叠柱形图；
  2. 案件情况 —— 每周新规 / 完了柱形图 + 累计完成折线（次坐标轴）；
  3. 时间去向 —— 范围内按依頼元的环形图（依頼元超过 6 个时，小的合并为「その他」）；
  4. AI 使用量 —— 每周 AI 费用柱形图（token 数放在 ④数据，不上图）。
- 图表数据全部引用 ④数据 sheet 的单元格区域，Excel 里点开可看数值。

### ② 每周一览

一周一行，**新的周在上**：周 | 日期范围 | 一句话说明 | 工时 | 新规 | 完了 | 主要案件（工时前 3 的案件名）。

### ③ 案件一览

范围内有工时或有状态变化的全部案件：依頼元 | 案件名 | 项目 | 状态 | 受領日 | 完了日 | 范围内工时 | 累计工时 | 成果物。排序：依頼元，再按受領日。

### ④ 数据

图表底表：按周 × 依頼元的工时、每周新规 / 完了 / 累计完成、每周 AI 费用与 token、范围内依頼元合计。放在最后一个 sheet，样式从简但整齐。

## 4. 一句话说明（oneliner）

- 每周一句，日文 / 中文约 40 字，英文约 25 词；写这周推进了什么，不写过程，不编造。
- **存储**：migration `0017`，`report_digests` 加列 `oneliner TEXT`（只在 `day = ''` 的周行使用）；登记进 `server/src/i18n/registry.ts`，三语翻译与润色（手改后）自动生效。
- **生成**：与本周概要同一次生成产出——
  - 本机 `scripts/digests-local.mjs`（当前 `DIGESTS_AUTO=off` 时的主路径）：schema 加 `oneliner`，写回接口 `PUT /api/reports/:week/digests/week/generated` 带上它；
  - Worker 路径（`server/src/report/digests.ts`）同样加字段，保持两条路径一致。
- **手改**：週報页本周概要处可编辑一句话说明；`PATCH /api/reports/:week/digests/week` 增加 `oneliner` 字段；手改后走润色。
- **补生成**：上线后跑一次补生成脚本，只填 `oneliner IS NULL` 的周，不动已有概要。
- **缺失时**：下载时该格用「主要案件名」兜底，不留空。

## 5. 视觉

### 共同规则（所有风格都遵守）

- 隐藏网格线；统一列宽、行高与留白；冻结表头行。
- 字体 游ゴシック（Yu Gothic）——Windows / Mac Office 都自带。
- 数字格式：工时 `0.0`，件数 `0`，费用 `$#,##0.00`，日期 `yyyy-mm-dd`。
- 图表：无外框、去掉多余网格线、图例位置固定、配色来自样式常量。
- 打印：A4 横向，宽度缩到一页。

### 定稿流程

1. 用 prod 真实数据生成 3 份样稿（只含 ①概览 + ②每周一览，图表 2 张）：
   - **素白报告风**：白底、深灰文字、单一强调色；
   - **深色看板风**：概览深底，与网站「信息牌」气质呼应；
   - **杂志数据风**：大号 KPI、细线分隔、克制配色。
2. 用户在 Windows / Mac Excel 打开对比，挑一份或指定混搭。
3. 锁定为 `style.ts` 的样式常量，后续 sheet 按同一套常量补齐。

样稿同时是图表注入代码的第一次实机验证：任一版 Excel 弹「需要修复」即视为失败，必须修到不弹。

## 6. 代码结构

```
server/src/report/range/
  data.ts      纯函数：一次 batch 读出的 tasks/sessions/notes/verdicts → 按周汇总（复用 weekly.ts 的按周计算）
  sheets.ts    ①–④ 的单元格内容（三语 labels）
  style.ts     样式常量（样稿选定后锁定）
  charts/
    chart-xml.ts   DrawingML 生成：柱（堆叠/簇状）、折线（次轴）、环形；输入 = 数据区域 + 系列 + 样式
    inject.ts      把 chart / drawing 部件和关系注入 exceljs 输出的 zip（[Content_Types].xml、rels）
  xlsx.ts      组装：exceljs 写表 → inject 图表 → Buffer
server/src/routes/report-downloads.ts   新路由 /api/reports/range/xlsx
web/                                     ↓xlsx 弹层：起止周 + 语言
scripts/oneliner-backfill.mjs            补生成
```

- 数据读取：**一次 `db.batch`**（与 `weekly.ts:81` 相同的 4 条），之后全在内存按周切分，D1 查询数不随周数增长（Workers Free 每次调用 50 条上限）。
- 图表生成器不认识业务数据，只认「区域 + 系列 + 样式」，单独可测。

## 7. 测试与验收

- **对拍**：range 汇总的每一周工时 / 新规 / 完了，与现有单周周报（`/api/reports/:week/weekly`）逐周相等，用 prod 真实周（≥4 周）跑一次。
- **结构**：生成的 xlsx 用 exceljs 读回，检查 sheet 名、关键单元格、`xl/charts/chart*.xml` 与 drawing 关系齐全；图表 XML 对 OOXML 关键结构断言（系列引用区域正确、类别轴 / 值轴成对）。
- **接口**：参数校验（格式、顺序、上限）、三语 labels、无数据周、只有一周。
- **规则 A**：oneliner 是整周内容的高压缩 → N=8 周独立抽检（无新增事实、名字和数字不改、意思没丢），结果存 `docs/projects/2026-10-13-xlsx-range/evidence/step_NN_audit.md`。
- **实机验收（最终关）**：用户在 Windows Excel 与 Mac Excel 各打开一次：不弹修复提示、图表显示正确、打印预览一页宽。

## 8. 风险

| 风险 | 对策 |
|------|------|
| Worker CPU 时间限制，周数多时生成 xlsx 超时 | 实测 4 / 12 / 26 / 52 周的耗时；超限则精简 ④数据 或降低周数上限 |
| 手写 DrawingML 在某版 Excel 弹修复 | 样稿阶段就两版 Excel 实机打开；chart XML 只用最保守的元素子集 |
| 依頼元过多导致堆叠柱 / 环形图难看 | 前 6 个依頼元 + 「その他」 |
| oneliner 生成质量 | 规则 A 抽检；可手改 + 润色 |
| 旧周没有 oneliner | 补生成脚本 + 主要案件名兜底 |

## 9. 不做（YAGNI）

- 不保留日别作業 / 成果物 / 稼働明细 sheet。
- 不在 xlsx 里读手改格子。
- 不做图片图表、不做 Numbers / Google 表格兼容调优。
- 不改週報页面的单周预览与 PDF。

## 11. 本周日别（2026-10-15，用户批准）

「本周」= 区间的最后一周（`weeks.at(-1)`，即週報的那一周：周六 → 周五，每天从 05:00 JST 开始）。没有作业的日子（含进行中那周的未来日子）为空 / 0。

- **数据**（`data.ts` `lastWeekDays`）：`RangeData.days`（7 天，旧→新）每天 `hours`（实时间，含作业备忘，与该周 hours 一致）、`by_series`（与周的依頼元系列同序，同一 keysOf / foldSeries 映射）、`by_task`（与 `day_tasks` 同序）、`start` / `end`（当日 00:00 JST 起的小时数，25.5 = 次日 01:30）。`day_tasks` = 该周按实时间分钟数的前 6 个案件（同分按 id），其余并入「その他の案件 / 其他案件 / Other tasks」，未关联时间（含已删除案件的时间）计入「未紐付」。
- **开始 / 结束规则**：取会话的 active intervals，没有时用 `started_at + 分钟`；裁剪到当日 [05:00, 次日 05:00)，因此跨 05:00 的会话在前一天结束于 29:00、后一天从 5:00 开始；按分钟取整。`minutes_override` 的会话与 wall.ts 一致，全部时间只记在 `started_at` 所在的 05:00 日（区间为 `started_at + override 分钟`，在该日 29:00 处截断），后一天不受影响；override 为 0 不计。作业备忘不计入开始 / 结束。
- **颜色**：案件 = 徽章色（`tasks.badge_color` → `LINE_PALETTE`，没有时用 id 的哈希色），再按网页 `inkOf` 向 #0f1c2e 混 28 % 以适合纸面（`server/src/badge/palette.ts`，与网页由 parity 测试钉住）；「その他」「未紐付」用样式的固定色位（`s.series[6]` / `[7]`），依頼元图与周图同色。
- **データ**：share 块下方「当週の日別」标题 + 表头 + 7 行：日付（yyyy-mm-dd）、曜日（`M/D (曜)`，图表类别轴引用此列）、稼働時間、每个依頼元系列一列、每个案件一列（表头即图例：标题超过 16 字截断加「…」，完整标题见案件一覧；案件列的未紐付加「（案件）」后缀以区别依頼元列）、開始時刻 / 終了時刻 / 稼働幅（以「天」为单位的小数，格式 `[h]:mm`；无会话的日子留空）。
- **当週業務内容**：案件表与注释之后「当週の日別 / 本周日别 / This Week by Day」标题，三张图（各附一行依据注释）：左上 每日工作时间（按委托方）堆叠；右上 每日工作时间（按案件）堆叠；左下 每日开始 / 结束时刻（浮动柱：透明的开始段 + 强调色的跨度段，`[h]:mm` 纵轴从 5:00 起每 3 小时一格，上限为不低于最晚结束的下一格，至少 8:00）。左侧图占 A–D 列、右侧图占 F 列（各 120 宽）。
- 工作簿共 7 个图表部件（表紙・概要 4 + 当週業務内容 3）。
