# 界面重设计 设计书（布局 A · 表 / 里 · 预判下一步）

2026-10-05。由 10/2–10/5 的 brainstorm 原型收敛而来，每一项都经用户在原型上确认。原型在 `.superpowers/brainstorm/8687-1791173322/content/`（附录 A 对照表），过程记录见 `2026-10-03-ui-redesign-handoff.md`、`2026-10-05-ui-redesign-handoff.md`。

## 1. 目的

现在的网页能用，但信息散、层级平、动作要找。重设计要同时做到两件事（用户原话的两头）：

1. **好看到"没人用过"**：整面 LED 信息牌、真点阵中日文、Liquid Glass、有过程的动效。
2. **一眼看懂、顺手**：信息密度高但不乱；牌面会按时刻和记录状态，把"现在该做的事"推到最前。

另外加一个**表世界**：给别人看时，同一块牌切成严肃的「医疗 + 数据分析」风。

### 范围

- 做：
  - 新外壳（顶栏、浮动 Dock）和七个页面：此刻 / 时间线 / 案件 / 计划 / 週報 / 统计 / 说明。
  - 表 / 里两个世界、两套动效、设置页、预判下一步（含规则编辑）。
  - 中 / 日 / 英三语界面。
  - 设置存服务端；週報下载记录。
- 不做：
  - 手机布局。保证不崩，不专门设计。
  - PDF 导出：另行设计，不复用表世界。
  - 「立即收集」按钮：属于 Go 版 collector 的方向，另立项。
  - 多用户。
  - 改动 CLI / harvest 的数据结构。
- 前置：`2026-10-01-ui-friction-draft.md` 的 A 类逻辑问题（A1–A5）先单独修完，不混进重设计。

## 4. 视觉系统

### 4.1 牌面与晶格

- **底色**：`#040506`，上面铺一层暗点阵，作为未点亮的 LED 场。
- **结构**：只用细线（`rgba(255,255,255,.06)`）和空行分区，不用卡片。
- **晶格**：所有点阵对齐同一张 3px 晶格，以文档原点为基准（`snap`）。
- **点阵字号**：只有三种。
  - 主角：8 网格 × 2，大数字用 2×2 点簇。
  - 区块标题：12 网格。
  - 正文：10 网格。
  - 中日文不小于 10 网格。

### 4.2 层级

| 档 | 亮度 | 光晕 | 用于 |
|---|---|---|---|
| L0 主角 | 100% | 强 | 运行时长、时钟、唯一的告警 |
| L1 数据 | 90% | 弱 | 案件名、时刻、金额 |
| L2 标签 | 44% | 很弱 | 区块标题、列名、次要信息 |
| L3 环境 | 17% | 无 | 刻度、空闲点、路径 |

- 颜色只表达含义：
  - 琥珀 = 默认内容
  - 绿 = 运行中
  - 红 = 需要你处理（全屏只能有一处）
  - 线路色 = 案件，用在代号、案件行左边条、每日条带和本周柱上（子项目 4 用户 10/6 裁定：原型优先；时间线运行图同理），不做大面积底色
  - 状态色 = 案件 / 计划状态
- 不允许用颜色来表达「次要」。
- **运动预算**：每个区域最多一处在动。长名字只在悬停时滚动。
- **悬停联动**：悬停任何案件，它在全屏的每次出现都提亮（×2.3），其余降一档（×0.5）。
- **眯眼测试**：每页都要能通过；按 `Q` 可以随时检查。

### 4.3 玻璃

- 用 `glass2` 的配方：1px 光线描边（上亮下暗），在约 10px 的窄圈内做方圆形折射，模糊约 3px，外加一层大而柔的阴影。
- 只用于 Dock、悬停提示、抽屉、设置里的浮层。

### 4.4 字体

- **点阵**：Fusion Pixel Font（OFL），8 / 10 / 12 三种尺寸，SC 和 JP 各一套。
  - 界面文字用当前语言的字形：日语界面用 JP，其他用 SC。
  - 数据（案件名、摘要）始终用 JP。
- **正文排版**：用在抽屉、週報摘要、说明页这些地方。按 `:lang()` 选字体栈：
  - 日文：BIZ UDPGothic / Noto Sans JP
  - 中文：Noto Sans SC
- **表世界**：见 §5。

## 5. 表 / 里两个世界

### 5.1 原则

- 两个世界是**同一块牌的正反面**：分区、槽位顺序、层级完全一致，只换介质。
- 每个点阵槽位都有一个**墨字孪生**：同一段文字，渲染成普通 DOM 文本。
  - 里世界显示点阵，墨字对屏幕阅读器可见（视觉隐藏）。
  - 表世界显示墨字。
- 当前世界存在设置里（§9），可以用 `?world=omote|ura` 临时覆盖。

### 5.2 表世界的样子

| 里 | 表 |
|---|---|
| 黑底点阵 | 纸面 `#f4f5f7`，墨色 `#0f1c2e` |
| 四档亮度 | 四档墨色：`#0b1626` / `#0f1c2e` / `#5b6573` / `#97a1ae` |
| 绿 = 运行中 | 医疗青 `#0e7c86` |
| 红 = 需要你处理 | `#b8322a` |
| 线路色代号 | 带线路色左边条的小标签 |
| 点阵字号 8×2 / 12 / 10 | 40 / 20 / 15 px，等宽数字 |
| 点阵图表 | 实色条、细网格线、正文字体刻度；当前时刻用青色细线加标签 |
| 暗色玻璃 | 浅色玻璃（同一配方，提亮） |

- **表世界字体**：用户可选 IBM Plex（默认）/ Inter / Geist；中日文配 Plex JP / Noto Sans JP / Noto Sans SC。
- **可配置模块**：每页声明自己的模块（例如此刻页：运行中 / 下一步 / 今日安排 / 运行情报 / AI 费用 / 运行图），用户在设置里勾选表世界显示哪些，默认隐藏 AI 费用。被隐藏的模块在表世界里直接不渲染。某一栏的模块全部隐藏时，整栏收起。

## 6. 动效系统

### 6.1 四类触发 × 两个世界

| 触发 | 里世界可选（默认加粗） | 表世界可选（默认加粗） |
|---|---|---|
| 打开 / 切换页面 | **全暗启辉**、扫描刷新、解码扰动、涟漪、点阵变形、逐字滚动、翻滚、无 | **逐行浮现**、打字机、扫描、涟漪、淡入、无 |
| 切换语言 | **点阵变形**、全暗启辉、扫描刷新、解码扰动、逐字滚动、涟漪、翻滚、无 | **上推替换**、逐字滚动、打字机、墨水晕开、扫描、涟漪、淡入、无 |
| 数据刷新 | **翻滚**、点阵变形、逐字滚动、解码扰动、扫描刷新、涟漪、全暗启辉、无 | **逐字滚动**（只滚变了的字）、上推替换、淡入、打字机、墨水晕开、涟漪、无 |
| 表 ⇄ 里 | **扫描线揭示**、点 → 墨聚合、翻面、断电 → 打印（两个方向共用） | 同左 |

另有全局「速度」（0.25× / 0.5× / 1× / 1.5×）。

### 6.2 各效果的定义（实现以原型为准）

- **全暗启辉**：先熄灭（带余辉），停一拍，再像日光灯管启辉器那样不规则闪两三下后稳住。全页共用同一个节拍，按行有约 0.1 的先后错开。
- **点阵变形**：旧点阵与新点阵逐点配对（按 x 再按 y 排序，数量不等时用比例索引分裂 / 合并），沿弧线飞过去，飞行中点变小、拖光。
- **扫描刷新 / 涟漪**：按**整页坐标**计时，所以全屏看到的是一道扫描线、一圈波。
- **解码扰动**：旧点在随机时刻熄灭；新点先随机闪烁，到各自的时刻锁定。
- **逐字滚动**：每个字独立向上滚出、新字从下滚入，从左到右错开。
- **逐字滚动（表）**：只有变了的字符才滚，像里程表。
- **扫描线揭示**：青色超声 / CT 式光带从上往下扫。用 View Transitions 实现：新状态按 `clip-path` 揭开，光带是一个有独立 `view-transition-name` 的元素。
- **点 → 墨聚合**：在覆盖画布上，每个可见的 LED 点飞向墨字字形的采样点，飞行中缩小、褪去光晕、变成墨色；纸面从开关处以圆形展开。
  - 被隐藏模块的点烧亮一下后熄灭。
  - 墨字采样每一轮都重新查询 DOM：字体换上后页面会重排，墨字元素会被重新生成。

### 6.3 约束

- 系统开启「减少动态效果」时，一律直接切换。
- 时钟每秒跳动不走动效（避免持续抖动）。运行时长等数字按分钟变化，走「数据刷新」动效。
- 世界切换期间锁住再次切换（`busy`）。

## 7. 预判下一步

### 7.1 模型

```
快照 Snapshot ──► 规则 Rule[] ──► 建议 Suggestion[] ──► 排序取前 3 ──► 牌面「下一步」
     │                                   │
     └─► 模式 Mode（按时刻 / 星期）        └─► 告警（运行情报，只取 alert 规则）
```

- **快照**：由现有查询拼成，不新增 harvest 字段。包括：
  - 当前时刻
  - 本周时间线（含昨天、今天）
  - 未关联会话
  - 计划条目和今日安排
  - 机器收集状态
  - 週報下载记录（§10.2）
- **模式**：按时间窗和星期决定，显示在「下一步」标题上。默认四个：
  - 早上 06:00–11:00
  - 专注 11:00–18:00
  - 週報：周五 15:00 起
  - 收工 18:00 起
- **规则**：纯函数 `(snapshot, params) → Suggestion[]`。每条建议包含：
  - 目标（案件 / 会话 / 计划条目）
  - 文案键
  - 动作（关联 / 排进今日 / 开始 / 加入安排 / 打开週報 / 确认）
  - 分数
  - 「为什么」：一句话，写明读到了什么、在哪个时间窗
- **排序**：分数 = 规则权重 × 紧迫度（例如未关联的分钟数、距截止日的天数）。同一目标只留分数最高的一条，最多显示 3 条。
- **依据行**：「下一步」标题后显示「依据 14:20 · 2 个会话运行中 · 今日安排 1/2」。
- **运行情报**：只在有 `alert` 规则命中时变红，否则显示「运行正常 · 两台机器 14:00 已收集」。

### 7.2 默认规则

时间窗都可以改。

| id | 模式 | 条件 | 建议 | alert |
|---|---|---|---|---|
| `unlinked.yesterday` | 早上 | 上一个工作日的会话仍未关联（合计 ≥ 5 分钟） | 关联 | ✓ |
| `plan.unplaced` | 早上 | 每日 / 本周计划条目今天还没排进今日安排 | 排进今日 | |
| `task.waiting` | 早上 | 某案件最近一个会话的摘要命中等待类关键词（默认：確認待ち、待ち、等待、waiting） | 看回复 | |
| `dayplan.untouched` | 专注 | 今日安排里的条目今天还没有任何会话 | 开始 | |
| `unlinked.stale` | 全天 | 会话结束超过 30 分钟仍未关联 | 关联 | ✓ |
| `plan.stale` | 专注 | 计划条目标记为「上周遗留」 | 加入安排 | |
| `week.unlinked` | 週報 | 本周还有未关联会话 | 关联 | ✓ |
| `report.undownloaded` | 週報 | 本周週報还没下载过 | 打开週報 | |
| `nextweek.empty` | 週報 | 下周没有任何「本周」档的计划 | 排下周 | |
| `dayplan.confirm` | 收工 | 今日安排里 AI 判定的条目还没手动确认 | 确认 | |

### 7.3 用户自己调

设置页「预判规则」分组：
- 每条规则：开 / 关、时间窗、参数（例如分钟阈值、关键词），以及在列表里拖动调整权重。
- 每个模式：时间窗、星期。
- 「恢复默认」。

规则配置存在设置里（§9），不改代码就能调。每条建议悬停时显示「为什么」，并标出命中的是哪条规则，方便定位要改哪条。

### 7.4 「运行中」的口径

- 网页拿到的数据最多晚一小时（harvest 每小时收集一次），所以「运行中」的意思是：**截至最后一次收集，会话最后一次活动距离收集时刻不超过 10 分钟**（阈值可调）。
- 运行时长从当前这段活动的开始算到收集时刻。顶栏一直显示「MAC 18:00 已收集」，让人知道数据新到哪一刻。
- 运行图只画到「此刻」，不显示未来。

## 8. 三语

- 界面文案集中放在一张表里（`zh` / `ja` / `en`），按键取值。缺 `ja` / `en` 时回落到 `zh`，开发模式下在控制台警告。
- **语言**：存在设置里；`?lang=` 可临时覆盖；`<html lang>` 跟着切换。
- **数据**（案件名、摘要、路径）保持原文，始终标 `lang="ja"`。
- **日期 / 货币**：用 `Intl`，按语言格式化，时区固定 `Asia/Tokyo`。
- **点阵字形**：界面文字在 `ja` 下用 JP 字形，其他用 SC；数据用 JP。

## 9. 设置与持久化

- **存储**：设置存在 D1，按单用户一行 JSON，这样 Mac 和 Win11 两台机器共用。
- **接口**：
  - `GET /api/prefs`：返回设置；没有存过时返回默认值。
  - `PUT /api/prefs`：整体替换；服务端用 zod 校验，未知键丢弃，缺的键用默认值补齐。
- **前端缓存**：用 TanStack Query 缓存，同时写一份到 `localStorage`，首屏先用本地那份，避免闪烁。
- 内容：
  ```ts
  type Prefs = {
    lang: "zh" | "ja" | "en"; world: "ura" | "omote";
    fx: { load, lang, data };            // 里
    ofx: { load, lang, data };           // 表
    worldFx: "scan" | "ink" | "flip" | "print"; speed: .25 | .5 | 1 | 1.5;
    omote: { font: "plex" | "inter" | "geist"; hide: string[] };   // 模块 id
    predict: { modes: ModeCfg[]; rules: Record<string, RuleCfg> };
  }
  ```
- 迁移：`0009_prefs.sql`（`prefs(id INTEGER PRIMARY KEY CHECK (id = 1), json TEXT NOT NULL, updated_at TEXT NOT NULL)`）。

## 10. 技术架构

### 10.1 前端模块（`web/src/v2/`）

- React 集成：
  - `<Led>` 在 effect 里创建 `Board`，文字变化时调用 `set`，动效类型从设置读取。
  - 卸载时把这块牌从 rAF 循环里移除。
  - 画布尺寸由 `ResizeObserver` 驱动重排。
- **自画图表**（运行图、条带、柱图）每个都是一个组件，分别实现 `drawUra` / `drawOmote`；世界切换和尺寸变化时重画。
- **字体资源**：像素字体约 3.3MB（三种尺寸 × SC / JP），放在 `server/public/fonts/`。
  - 按需加载用到的尺寸和语言，配长期缓存。
  - 原型里的 `m` 变体没用到，不带。
  - 字体许可（OFL）的署名放在说明页。
- **无障碍**：
  - 墨字孪生就是可访问文本。
  - 画布 `aria-hidden`。
  - 焦点环在两个世界都清楚可见。
  - 抽屉沿用现有的 `focusTrap`。

## 13. 风险

| 风险 | 对策 |
|---|---|
| 首次加载像素字体较大 | 按需加载、长期缓存；如果还是慢，再考虑按常用字子集化 |
| 画布很多，Win11 上卡 | 只在动画时重画；点 → 墨聚合超过 3 万点时降采样；必要时改用 WebGL 点精灵（D12 允许） |
| 网页字体还在加载时，画布画不出字形 | 采样时等 `document.fonts.load`，每一轮都新建 context 并重新查询 DOM（原型里踩过） |
| 墨字类名与页面类名撞名 | 墨字一律用 `i-` 前缀（`i-g` / `i-r` / `i-dim` / `i-code` / `iblk`） |
| 规则误报变成噪音 | 规则 A 抽检；每条规则可以单独关闭；悬停显示原因 |
| 「运行中」最多晚一小时 | 显示收集时刻（§7.4）；实时性交给以后的「立即收集」 |
