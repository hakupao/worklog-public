# 手机版第 4 阶段 设计书：H1 视觉 + 采集心跳 + 遗留小问题

> 接 `docs/design/2026-10-13-mobile-design.md`（M7：「AI 味」留到第 4 阶段）和 `docs/projects/2026-10-13-mobile/RETROSPECTIVE.md` 的 Phase 4 backlog。手机版 `#/m/*` 已于 10/13 上线，本阶段不改路由、页面和数据层的结构。

## 1. 目的与成功标准

做三件事：
1. **视觉**：去掉用户点名的四种「AI 味」，换成 10/14 选定的 **H1** 方向（见 §2）。
2. **新信息**：此刻页加「本周案件」和「采集」两组。「采集」要求采集器每跑一次就向服务器报一次（心跳），Go 版和 Python 版都要加。
3. **遗留小问题**：修 retro 里列的 Phase 4 backlog（§6）。

成功标准：
- 用户 10/14 在浏览器里确认的原型 `docs/design/prototypes/2026-10-14/mobile-p4-h1-pages.html`（8 屏 × 浅 / 深），实机效果与它一致。
- 沿用第 1–3 阶段的底线：360 / 390 / 430px 下任何页面和弹层都没有横向滚动、没有文字溢出；可点区域 ≥ 44px；输入框 ≥ 16px；不依赖悬停。
- 「采集」的 24 个点如实反映采集器每小时有没有跑。没跑就是暗点，跑了但没有新 session 也是亮点。

不做：桌面版任何视觉改动；新增页面；改计划之外的写操作。

## 2. 已定决策（10/14 视觉讨论）

讨论过程在 visual companion 里走了三轮，原型都存在 `docs/design/prototypes/2026-10-14/`：
- 第 1 轮 A–D（印刷 / 仪器 / iOS 原生 / 终端），用户评价「都一般」。
- 第 2 轮融入 ascii.rest 的元素，出了 E–H 四个方向，用户选 H（iOS 原生 + ASCII 点缀）。
- 第 3 轮把 H 的数字和图标像素化，出了 H1 / H2 / H3，用户选 **H1**，并确认了 H1 推到全部页面后的效果。

## 3. 视觉实现

### 3.1 样式

- `web/src/m/styles/m.css` 整体重写，仍然全部挂在 `html.m` 下。文件头注释里的七条防溢出规则保留，并按新组件更新。
- 颜色令牌重新定义两套，选择器不变（`html.m` 是浅色，`html.m[data-m-theme=dark]` 是深色）。以下令牌删掉：`--glow`、`--blur`、`--card-bg`、`--card-line`、`--radius`、`--numf`。
- 以下样式删掉：`.m-backdrop` 和对应 DOM（`MobileApp.tsx`），`.m-eq`，`.m-pill`，`.m-chip`，`.m-ring`，所有 `@keyframes`（盲文转圈、光标闪烁和弹层用的除外）。
- `.m-card` 改成分组样式 `.m-grp`，组标题 `.m-cap` 放在组外。组件名可以在计划里细化，但每个页面的结构以原型为准。
- `fonts.ts` 改为加载 `Doto:wght@900`，两套主题都加载。
- `prefers-reduced-motion` 打开时，三处保留的动效也要停：转圈显示静止字符，光标常亮，弹层直接出现和消失。

### 3.2 新组件（`web/src/m/ui/`）

- **`DotNum`**：把字符串画成 5×7 圆点阵 SVG，字形覆盖 `0-9 . :`。字形表取自原型里的 `F57`，并修正为不带斜杠的 0。
  - SVG 的 `width` 设为 100%、`max-width` 等于自然宽度，`height` 自适应。这样 `999:59` 在 360px 下两列并排也能缩小，不会撑出容器（防溢出规则 4）。
  - 有 `role="img"` 和 `aria-label`，值为原字符串加单位。
  - 单位 `h` 用 Doto 小字跟在后面。
- **`DotBar`**：一行 n 个圆点，亮点数为 `round(p·n)`，宽度 100%。用于计划进度（n = 20）、案件和统计的耗时条（n = 32）。
- **`DotCols`**：统计页的每天柱子。每列 3 点宽、10 点高，今天那一列用强调色。
  - 每列仍是一个按钮，保留点选查看当天数值的功能，可点高度 ≥ 44px。
  - 本月有 28–31 列时，靠 SVG 的 viewBox 等比缩小，不出现横向滚动。
- **`DotSpark`**：此刻页本周 7 天的工作时间，每天一根 2 点宽、8 点高的点柱。
- **`DotIcon`**：底栏图标，位图取自原型的 `ICON` 表（11×10）。现有的 `ui/nav.tsx` 里的 `ICONS` 换成这一组。
- **`Seg`**：iOS 分段控件。每段是 `<button aria-pressed>`，高度 ≥ 44px（可点区域，视觉高度可以更矮），段数 2–4。
- **`Spinner`**：盲文转圈，由 CSS 驱动，`aria-hidden`。
- **`Num`**（数字滚动）删除。所有原来用 `Num` 的地方，改用 `DotNum`（大数字）或 Doto 文字（小数字）直接显示最终值。retro 里的「Num 第一帧闪烁」随之消失。
- **`Ring`** 删除。

### 3.3 逐页对照（以原型为准）

- **顶栏**：左边是 30px 粗体大标题，右边三个方括号按钮。
  - 主题按钮显示当前选择：`[自动]` / `[深]` / `[浅]`，用现有的 `m.theme.*` 键，需新增短形式。
  - 语言按钮显示 `[中]` / `[日]` / `[EN]`。
  - 桌面版按钮显示 `[桌面]`。
  - 每个按钮的可点区域 ≥ 44×44px。
- **此刻**：自上而下依次是：
  1. 组标题「今天 · 日期」，右侧是「同步 hh:mm」加光标。
  2. 大数字组：工作时间 / 累计耗时，下方一行是本周火花线和本周合计。
  3. 进行中。
  4. 今日安排：勾选行、进度条，组标题右侧有「全部 ›」。
  5. 本周案件。
  6. 采集。
  7. 今天：未关联 session 的条数。

  - 「同步 hh:mm」取所有机器中最近一次心跳的时间，没有心跳时用 `last_seen_at`。
  - 本周火花线和本周合计，用此刻页已经加载的本周时间线（`useTimeline(currentWeek())`）。
  - 本周案件用 `useDashboard(本周一, 今天)`，和统计页「本周」的缓存键相同，不多发请求。前 5 名之外的不显示。没有数据时整组不显示。
- **时间线**：DayNav；分段控件「全部 / 只看未关联」；分组列表，每行是时刻、标题 + 摘要、分钟数。
- **计划**：DayNav；勾选分组加进度条；新增输入框（分组样式，16px）加 `[添加]`；说明文字。
- **计划编辑弹层**：
  - 「内容」和「目标」两个输入框。
  - 「状态」用分段控件：自动 / 完成 / 部分 / 未做。
  - AI 判定的说明。
  - `[删除]`（按两次才删）和 `[保存]`。
- **案件**：搜索框；分段控件「进行中 / 搁置 / 完成 / 全部」；每行是标题、依赖元 · 最近日期、小时数加 `›`，下面一条圆点条。
- **案件详情 / session 详情弹层**：键值行放在分组里，数字用 Doto，只读说明放在弹层底部。
- **统计**：
  - 分段控件「今天 / 本周 / 本月」。
  - 大数字组：工作时间 / 累计耗时，下面是 tokens / 费用（Doto 22px）。
  - 每天的工作时间（`DotCols`，下方显示所选那天的数值）。
  - 按案件（`DotBar`，最后一行是未关联）。
  - 底部说明有几个 session。

## 4. 采集心跳

### 4.1 服务器

- **迁移**：新建表 `harvest_runs`。迁移编号用实现时的下一个空号：0018 已被 task-badges 设计书预订，如果它先落地就用 0019。

  ```sql
  CREATE TABLE harvest_runs (
    machine TEXT NOT NULL,
    at TEXT NOT NULL,          -- UTC ISO-8601, written by the server
    new INTEGER NOT NULL,
    updated INTEGER NOT NULL,
    PRIMARY KEY (machine, at)
  );
  ```
- **`POST /api/ingest/heartbeat`**：
  - 请求体 `{ machine, new, updated }`，用 zod 校验，字段非负整数。
  - 服务器在同一个 batch 里做三件事：
    - 写一行 `harvest_runs`，`at` 取服务器当前时间；
    - 用同一个时间更新 `machines.last_seen_at`（upsert），这样「没有新 session 但采集器在跑」也算同步过；
    - 删除该机器 8 天前的行。
  - 返回 `{ ok: true }`。
- **`GET /api/machines/runs`**：
  - 返回每台机器过去 24 个整点小时（按 JST，包含当前这一小时）的布尔数组，以及最近一次心跳的时间：`[{ name, hours: boolean[24], last_run_at: string | null }]`。
  - 机器列表取自 `machines` 表，没有心跳记录的机器 `hours` 全为 false，`last_run_at` 为 null。
  - 小时的分桶在服务器上算，有单元测试覆盖跨日边界。
- 两个新路由都走现有的 Access 鉴权，不加新的鉴权方式。

### 4.2 采集器

- **Go 版**：在 `collector/internal/api/client.go` 加 `Heartbeat(machine, new, updated)`。`runHarvest` 在 `harvest.Run` 成功之后、打印汇总行之前调用一次。
- **Python 版**：在 `src/worklog/api_client.py` 加同名方法。CLI 的 harvest 命令在 `harvest()` 成功返回后调用一次。
- **两版行为一致**：
  - 心跳**不放进 outbox**（`park=false`），发送失败只记一行警告，不影响退出码。补发一个过去的心跳没有意义，缺的那一小时就该是暗点。
  - `--refresh-meta` 和 api 不可达（退出码 2）这两种情况都不发心跳。
- **对拍**：`collector/parity` 比对 Go 和 Python 的 HTTP 记录。两边同时加上心跳后，按现有流程重新生成 golden（`collector/testdata/gen_golden.py`），并确认 diff 只多出心跳请求。
- **Win11**：Python 版需要 `git pull`（历史改写之后要用 `reset --hard`，见 memory）。按现有做法写一份 runbook 交给 Win11 端执行，结果写回仓库。Go 版切换（Task 16）时自然带上心跳。

### 4.3 手机端显示

- 每台机器一行：机器名、24 个点（从左到右是最早到最近一小时）、最近一次心跳的时间。用现有的 `isSyncStale` 判断，超时时这行的时间显示为橙色。
- 某台机器没有任何心跳记录（采集器还是旧版）时：点不画，时间位置显示「采集器未更新」。
- 「采集」组替换掉现在此刻页的「同步 · 机器名」那几行。「未关联」那一行保留，放进最后的「今天」组。

## 7. 测试与验收

- **单元测试（vitest）**：
  - `DotNum`：字形、aria-label、缩放属性。
  - `DotBar`：亮点数在 0、中间值、满格时都正确。
  - `Seg`：`aria-pressed` 和键盘操作。
  - B1、B2、B5、B8 各自的测试。

  - 现有测试里断言 `Num`、`Ring`、`m-chip` 的地方，改成断言新组件。
- **服务器测试**：心跳写入、8 天清理、`last_seen_at` 更新、24 小时 JST 分桶（含跨日）、请求体校验失败返回 400。
- **采集器测试**：Go 和 Python 各自的心跳单元测试（成功、失败只警告、`--refresh-meta` 不发）；parity 重新生成 golden 后全部通过。

- **人工验收（硬闸）**：部署后用户在 iPhone 上逐屏核对浅色和深色，和原型对比；在此刻页看到 Mac 和 Win11 两行采集点（Win11 要等 Python 版拉取新版本之后）。

## 8. 交付顺序

1. **心跳**：服务器（迁移、两个路由）→ Go 版 → Python 版 → parity。这部分可以单独上线，旧的手机界面不受影响。
2. **视觉基础**：令牌、`m.css` 重写、新组件、顶栏、底栏、去掉动效。
3. **逐页套用**：此刻（含两组新信息）→ 时间线 → 计划和编辑弹层 → 案件和详情 → 统计。
4. **遗留小问题** B1–B8。
5. **收尾**：溢出检查，iPhone 验收，部署，Win11 runbook。

规模大约 12–15 步，按 Tier 2 执行（PLAN / _progress / evidence / RETROSPECTIVE）。
