# 此刻 首页重排 设计书

> 重新排布首页「此刻」（`#/v2/now`）：加入日期和倒计时类信息，以及一幅随时段轮换的 ascii.rest 场景图。表、里两个世界都要做。

## 1. 起因与目的

- 用户 10/20 原话：首页「右上角有些空」，想放时间和日期信息，包括本月日历、今天几号、本月第几个营业日、离下一个祝日还有几天、离下一个周末还有几天，以及调研后值得加的其他项。
- ascii.rest 的 scene 图在里世界**全部循环显示**；表世界放**同一个场景的表世界版**。
- 范围：**整个首页重排**，不只是把东西塞进右上角。
- 日历只按**日本祝日**算。

成功标准：
- 扫一眼就能读到今天是哪天、本月营业日进度，以及最近的几个日子还有几天。
- 场景图跟数据有关联（按当前时段选图），不是装饰贴图。
- 1512×945 一屏放下：dock 不挡内容，不出现横向滚动；1280 宽不破版。
- 不出现 AI 卡片网格感（§6）。

## 2. 选定方案：C3a（三轮样稿后，用户 10/20 选定）

来源：
- 可点原型 `docs/design/prototypes/2026-10-20/now-c3a.html`。直接用浏览器打开即可，字体从 `web/src/v2/led/fonts/` 读取。
  - `?world=omote` 切到表世界
  - `?scene=color` 切到彩色
  - `?scene=<id>` 指定场景
  - `?now=2026-10-20T09:05` 改时刻（只影响日期信息和场景时段，不影响样本里的大钟）
- 原型数据：运行部分用的是 10/2 的真实样本，日期改标成 10/20 18:45；月历每天的工时是合成数据；祝日是手写的日期列表。正式版全部换成真实数据（§4）。
- 选择过程：
  - 第一轮 A 车厢双屏 / B 发车标通栏 / C 图纸标题栏，用户选 C（B 明确不要）。
  - 第二轮基于 C 做了 C1 精修、C2 大图、C3 合并底栏、C4 镜像，用户选 C3。
  - 第三轮为解决 C3 中间的竖条空白做了 C3a / C3b / C3c，用户选 C3a。

### 2.1 版面（从上到下）

| 区域 | 内容 |
|---|---|
| 页头 | 不变：此刻 · 日期 · 两台机器的收集状态 · 大钟 |
| 左栏上（约 58% 宽） | **场景图版**：宽度撑满左栏，200 列，只显示第 12–88 行（横幅）。点距 = 栏宽 / 200，允许小数，1512 下约 4.1px。没有边框，没有标题栏 |
| 图版下一行 | 图注：`Fig. 14 — 东京 · 雨 · 日没 17:00 · 夜 +1:45`。顶边一条 1px 细线，在一次轮换周期（25 秒）内从左长到右，表示离下一幅还有多久。放不下时先隐藏「夜 +1:45」 |
| 左栏下 | **今天的运行图**（现有 `now.dia`）。时间轴拉伸，轨道一直画到右侧工时列前，不再在 21:00 后留空。点距保持 3px，和底板点阵对齐，点数按宽度算 |
| 右栏（约 42% 宽） | 不变：运行中 → 下一步 → 今日安排 → 运行情报 → AI 费用 |
| 底栏（横贯全宽） | **一张合并的图纸标题栏**，用细线画成一张表，共 30px 表头 + 5 行 × 27px。左区「星历 · 倒计时」，中区月历，右区标题块。右区左侧的竖线和上方左右栏的分界线对齐，上下连成一条 |
| dock | 不变 |

> 结构变化：运行图从页面底部通栏移到左栏，右栏模块不变。

### 2.2 底栏三区

- **星历 · 倒计时**（发车牌式的行，列为「种别｜内容｜日期｜余｜营业日」）：
  - 行：給料日、周末、月末締め、祝日、长假
  - 按日期由近到远排序
  - **越近越亮**（Flighty 规则），亮度按远近排名分档：最近的最亮，最远的最暗
- **月历**：
  - 星期行是表头；每周一行，正好落在表的 5 行上（6 周的月份要处理，见 §7）
  - 每天的亮度表示当天工时，分 4 档
  - 周末和祝日压暗；今天加标记；未来的日子只画轮廓或最暗档
  - 表世界加一列 ISO 周号
- **标题块**：
  - 日期「2026-10-20 火」是唯一的主格：最大、最亮、占两行
  - 其余各格：和暦、W43 · FY2026 Q3、营业日 13/21 剩 8、记录 15/20 天、日没、日出、版次、坐标、亮度说明
  - 里世界只用暗细线分隔，列宽不等；表世界可以用带框的表格

### 2.3 表世界

- 版面和槽位顺序与里世界一致，切换时点阵过渡成墨迹（沿用现有 world 机制）。
- 场景图画成彩色调幅网点（点的大小表示浓淡，不铺底色），配同一行图注。
- 运行图用心电图纸式双层网格。
- **表世界字号比里世界小，所以表世界会比里世界多出空白。用户 10/20 认为这无法避免，接受。** 不要为了填满表世界去另外改版面。
- AI 费用在表世界按现有偏好默认隐藏（`omote.hide` 含 `now.cost`），不改。

## 3. 场景图

- 来源：npm 包 `ascii.rest`（MIT，作者 bas3line）。npm 0.4.0 有 15 个场景，网站上列了 34 个；另外 19 个在作者 GitHub main 上还没发版，10/22 起按 MIT 原样复制到 `web/src/v2/scene/vendor/`（来源提交 c556be4，只改了类型 import），34 个全部轮换（用户 10/22，品牌标志主题的也要）。不直接依赖 GitHub：npm 会记成 ssh 地址、npm 11 默认拦截 `prepare` 编译、安装要等约 5 分钟。npm 发版带上这些场景后删掉 vendor/（测试会提醒）；届时 Fig 编号会按包里的顺序重排。
- 每个场景是 200×100 的字符帧（字符 ` ·•●`，外加每格的调色板索引），15 fps。
- **按时段选图**：用东京的日出、日没时间把一天分成黎明 / 白天 / 黄昏 / 夜四个时段（原型规则见 `prototypes/2026-10-20/time.js` 的 `period`），只在当前时段的场景里轮换，每 25 秒换一幅；顺序随机（用户 10/22），不会连续两次是同一幅，进入页面和换时段时的第一幅也随机。时段归属（10/22 起 34 个，按各场景 note 判断）：
  - dawn（5）：alpineDawn、tajDawn、mistyForest、jalMahal、saltFlat
  - day（7）：deepReef、earthrise、jungleFalls、kiteFestival、blackPrism、planetScale、saturnRise
  - dusk（9）：kyotoDusk、oceanSunset、stormPlains、varanasiGhats、cloudSea、lakePichola、nightHighway、greenStorm、prismCity
  - night（13）：auroraFjord、desertNight、lanternLake、marineDrive、nightCoast、tokyoRain、amerFort、commandCity、edgeOrbit、gangaurGhat、snowTrain、volcanoNight、lavaWall
- **里 · 彩色**（10/22 起唯一画法，单色与切换键已删，见 D5）：用场景原调色板，按字符权重决定透明度（10/22 起不再做自动色阶：两个世界都只看字符权重和调色板颜色）。彩色同样要让数据比图更亮：整体透明度设上限，有警报时同样降一档（原型 C1 之后彩色在警报时没有压暗，比琥珀色数据更抢眼，正式版要修）。
- **表**：彩色调幅网点（用户 10/22 第五轮选定，原型对比见下）。直接画在页面纸色 `#f4f5f7` 上，不铺底色，所以图没有矩形边。每格先算出目标色（里世界里这一格看起来的颜色），再印成「油墨」：油墨亮度不超过 OKLab L .52、饱和度提高，点的面积等于这种油墨在纸上达到目标亮度所需的覆盖率（点径最大 1/√π ≈ 0.56 格距，小于 0.3 px 不画；整帧没有明暗差时按最浅一档印，不会印成一整块）。结果是亮处为稀疏小点、暗处点大到连成一片，纸缝不会连成白网格。
  - 黄昏、夜（R3）：目标色 = 里世界的样子叠在表世界深墨 `#0b1626` 上。
  - 黎明、白天（R1）：把本帧里世界的明暗范围重新映射到 L [.40, .86]，明暗顺序不变，越亮饱和度提得越高，最暗处带一点墨蓝（不是中性灰），再裁进 sRGB。
  - 纸面，警报时不压暗。
  - 被否掉的方向（10/22，用户看过真实页面截图）：墨点网版叠原色（①，两套系统打架）；原样印在纸上露白纸缝（P1，白缝连成亮网格、刺眼）；深墨整版底（P1c，像一块黑矩形）；缝里填本色浅调 / 四周渐隐（Q1–Q4）；调频点彩（R2，棋盘纹）。
- 页面隐藏时（`document.hidden`）暂停；`prefers-reduced-motion` 时只画一帧静止图。
- 图注三语齐全（zh / ja / en，原型 `scenes-entry.js` 的 `CAP` 表）。

## 4. 时间信息的定义

- **祝日**：用 `@holiday-jp/holiday_jp`（MIT，数据覆盖 1970–2050；2028 年以后的春分、秋分是预测值）。顺手修正 `web/src/v2/predict/time.ts:22`「public holidays are not known here」，让预判的「上一个工作日」也跳过祝日。
- **公司长假**：在设置页编辑（用户 10/20 选定），是一个列表，每项为名称（三语或单语）+ 起止日期。默认预置 年末年始 12/29–1/3、お盆 8/13–8/16；GW 默认取 4/29–5/5 的国民祝日段。存进现有 prefs（`/api/prefs`，D1 里的偏好表），需要同步改 `server/src/prefs/schema.ts`。
- **給料日**：每月 25 日，可在设置页修改（用户 10/20 选定），和公司长假放在同一个设置区。遇到休息日提前到前一个营业日。
- **营业日** = 非周六日、非祝日、非公司长假。显示：
  - 本月第 n 个营业日 / 共几个，剩几个
  - 今天不是营业日时显示「今天休息」，不显示第 0 个
- **记录天数**：本月到今天为止，有记录的天数 / 已过的天数。「有记录」= 当天有任意 session（包括未关联的）墙钟时间 > 0。（我的决定）
- **月历工时**：每天的工作时间（墙钟时间，日界 05:00，和週報一致），按 4 档量化：0、<4h、<7h、<9.5h、≥9.5h（原型的阈值，builder 可以按真实分布调整）。
- **倒计时**：
  - 周末：到下一个周六
  - 祝日：到下一个祝日，显示名称
  - 长假：到下一个公司长假的第一天，显示名称和天数
  - 月末締め：本月最后一个营业日
  - 給料日：设置里的那一天（默认 25），遇到休息日提前到前一个营业日
  - 「余」= 自然日差；「营业日」= 中间夹着的营业日数（两端都不算）
- **其他**：ISO 周、财年季度（4 月开始）、和暦（`Intl` ja-JP-u-ca-japanese）、东京日出日没（NOAA 近似公式，误差约 ±1 分钟）。
- 时刻一律按 JST 计算。

## 5. 动效

- 场景换图：渐变或按列擦除，时长 ≤ 600ms。
- 倒计时数字变化时，只翻动变了的那一位（Solari 翻牌式），不要整行重绘。
- 不加强辉光、不做悬停放大（之前因为影响阅读被否决过）。
- 其余沿用现有 LED 和表里切换动效。

## 6. 禁止项（用户已认可的设计规则）

- 圆角、填色、带阴影的块；等大的数据小卡片（「大数字 + 小标签」）；把 W43 / FY / 和暦 做成徽章一排；每格都是圆角的日历；带边框和标题栏的场景「小部件」；左右对称的等大分区。
- 里世界是一整块连续的深色 LED 点阵板：只用细线和间距分区，4 档亮度表示层级；颜色有含义：琥珀是主色，红色只用于警报，线路色表示案件。
- 玻璃效果只用在浮动 dock 上。
- CJK 文字必须走现有 LED 点阵渲染（含 Win11 字形修正），不另写渲染器。

## 7. 交给 builder 决定

- 场景渲染器怎么接进现有 LED 管线（`web/src/v2/led/`）、怎么参与表里切换的过渡。原型里场景 canvas 不是 LED.Board，所以切换时会跳一下，正式版要解决。
- 小数点距的场景点阵和底板 3px 点阵不对齐，近看比底板粗一号。用户看过、接受了 C3a，可以保持；能对齐更好。
- 底栏怎么放下 6 周的月份：压行高，或者让月历多一行而左右两区留空行。
- 1280 宽的退化方案：原型在 ≤1400 时缩小日期字号、隐藏部分次要格。
- 新的数据从哪里取：工时用现有 timeline / dashboard 接口，还是新开一个月度接口。
- 情境模拟（SimRail）在新版面里的位置：它只是演示控件，不能挡住主要内容。
- 新增模块的 id（例如 `now.scene`、`now.time`），以及它们在表世界默认显示还是隐藏。
