用户原话：

1. report 页，我其实希望每个格子内的文字都能被看到，现在有些被省略了，不太好。
2. 想提高总结的质量，要根据项目总体的目标 / 工作情况总结，而不是单纯的 session 局部总结。

6. 所有生成的总结都要少用 AI 味浓的表达和技术用语，尽量让不懂技术和专业词汇的人也能看得懂，比如人事等管理岗（这只是举例，并不是给他们看）。

## 1. 周报页格子显示全文（C1）

### 1.1 范围

周报页（`web/src/v2/pages/report/`）里现在用 `<Led clip>` 或单行截断的格子：

| 视图 | 格子 |
|---|---|
| 案件一覧 `TasksView` | 案件名、依頼元、プロジェクト |
| 日別作業 `DaysView` | 案件标题（含「未关联」）、日总结行 |
| 成果物 `DeliverablesView` | 案件名 |
| サマリー `SummaryView` | 依頼元行 |
| 周总结块 `Digests.tsx` | 周总结全文（多行） |

### 1.2 表世界

格子是普通文字：去掉 `white-space:nowrap` / `text-overflow:ellipsis`，允许按词换行（`overflow-wrap:anywhere`，CJK 自然断行）。同一行的格子按最高的撑开，列宽不变。

### 1.3 里世界：`Led` 折行模式

- `Led` 新增 `wrap` 属性（与 `clip`、`fit` 互斥）。宽度变化时按可用宽度把文字切成若干行，每行一块点阵板，上下依次排列，行高 = 现有单行高度。
- 切行是纯函数 `wrapSegs(segs, avail, widthOf): Seg[][]`，放在 `web/src/v2/led/compose.ts`，和现有 `clipSegs` 同一套宽度测量。规则：CJK 字符之间可断；拉丁词不拆，单个词比整行还宽时按字符硬断；行首不留空格；`\n` 强制换行（总结是多行文本）。
- 动效：折行板的首次出现沿用该 `Led` 的 load 动效；换语言、数据变化时整块重排，不逐行做 marquee。
- 其它页面不传 `wrap`，行为不变。

### 1.4 测试

- `wrapSegs`：纯中文、纯日文、中英混排、单个超长英文词、`\n`、空串、宽度刚好等于一行。
- 报告页各视图：长文本渲染后不出现截断标记（表世界无 ellipsis 样式，里世界 `Led` 收到 `wrap`）。

## 2. 总结按案件写进展（C2–C4）

### 2.1 输入

在现有输入（当天各 session 有效摘要、备注、所属案件名、各案件当天墙钟分钟）之外，加上：

| 来源 | 内容 | 读取 |
|---|---|---|
| 案件本身 | 当天 / 本周有工作的各案件：案件名、依頼元、状态、受領日、完了日、備考（`thinking`）、累计工时 | `buildWeek` 已读 tasks，直接用 |
| 计划里的目标 | 挂在这些案件上的 `plan_items`（经 `plan_item_tasks` 或 `plan_items.task_id`），状态为 active，或在本周内完成；带档位（今日 / 本周 / 近期 / 远期）与完成状态 | 一次 batch |
| 今日安排的判定 | 当天的 `day_plan_items`：文本、详情、AI 判定（done / partial / none）、进展说明 | 同一 batch |
| 上周的周总结 | `report_digests` 里上一报告周的周总结（`day = ''`） | 同一 batch |

日总结的输入只取当天相关的部分（当天有工作的案件、当天的今日安排）。周总结的输入是 7 条日总结 + 本周各案件工时 + 案件信息 + 计划目标 + 上周周总结。

输入文本拼成固定顺序的纯文本，`inputs_hash` = 它的 sha-256（与 S2 相同机制）。输入变了 → 指纹变 → 未手改的总结视为过期。

D1 预算：`digestsOf`（周报预览算"过期"）和生成时各多一次 batch（3 条语句），在 Workers Free 每次 50 条查询内。

### 2.2 输出格式与提示词

- 周总结：每个有实质进展的案件一行，形如 `■ 案件名：推进到哪（对照目标）。卡点 / 下一步（有才写）`。只做了零碎小事的案件不单列，合成一行 `■ その他：…`。没有进展的周写一行说明。
- 日总结：同样按案件，通常 1–3 行；只有一件事时一行。
- 提示词要求：只写目标层面的进展与结果；不写操作步骤、工具名、文件名、命令；不复述 session 摘要；有计划目标时说清与目标的距离；人名、案件名、版本号原样保留。语言：日语原文。
- 结构化输出：JSON `{ "lines": string[] }`，服务端用 `\n` 连接存入 `report_digests.text`。
- 安全上限：日 400 字、周 800 字（按 code point）。**实施修订（R14）：日 800 / 周 1600，首次真实运行中旧上限截掉了真实内容后调高；翻译字段随之放宽（text 6000 / pdf_text 3000）。**超出时在最后一个完整行处截断，不重试。

### 2.3 生成开关与本机生成（C5）

- `wrangler.jsonc` 的 `vars` 加 `DIGESTS_AUTO: "off"`。`refreshDigests` 只在 `"on"` 时调 API；关着时 cron 跳过生成，周报页的 ↻ 只把该条标成待重写（`edited = 0`、`inputs_hash = ''`），等下次本机生成。
- 新接口（需要认证，CLI token 或 Access）：
  - `GET /api/reports/:week/digest-inputs`：返回本周各工作日的 `{ date, input, hash, current }`，以及按当前已存日总结拼出的周输入 `{ input, hash, current }`；同时返回日 / 周两份 system prompt 和 JSON schema，本机工具不另存提示词。
  - `PUT /api/reports/:week/digests/:day/generated`：body `{ text, inputs_hash, model, zh, en }`。`inputs_hash` 必须等于服务端此刻算出的指纹（否则 409 `stale`）；该条已手改（`edited = 1`）→ 409 `edited`，不覆盖。写入 `report_digests`（`edited = 0`）并 upsert `translations`（`source_text = text`、`source_lang = ja`、`ja = text`、`zh`、`en`、`model`），翻译 sweep 视为新鲜，不再调 API。
- 本机工具 `scripts/digests-local.mjs`（Node，在仓库根目录跑）：
  1. 读 `~/.worklog/credentials.toml` 拿认证，`config.toml` 拿 `api_url`。
  2. 参数 `--from <week> --to <week>`（默认：有 session 的最早报告周 → 本周）、`--only-stale`（默认开：只重写指纹不符或待重写的）。
  3. 每周：取 digest-inputs → 逐日调用 `claude -p --model opus`（system prompt 来自接口，要求输出 `{ lines, zh, en }`：日语原文按行，加中文、英文译文）→ PUT 写回；日总结写完后重新取一次 inputs 拿周输入 → 生成周总结 → 写回。
  4. 并发 3；失败的条目记进日志、跳过，不中断整周；结束打印每周 生成 / 跳过 / 失败 数。
- 正式使用时把 `DIGESTS_AUTO` 改成 `"on"`，cron 用同一套输入与提示词经 API 生成（模型 `claude-sonnet-5-5`，与 S2 相同）。

### 2.4 展示

- 网页：周总结块与日別作業的每日行显示全文多行（§1 的折行），读 `text`。手改编辑框改为多行文本框，保存时按行存。
- PDF：读 §2.6 的 `pdf_text`，没有时退回 `text`；`clamp` 步骤仍是最后兜底。

### 2.6 PDF 专用版本（C6）

- 迁移 `0013_digest_pdf.sql`：`report_digests` 加列 `pdf_text TEXT`（可空）。翻译注册表加 `digest.pdf_text`，三语同样经本机生成写入。
- 生成时同一次调用一起产出两份：网页版 `lines`（全文）和 PDF 版 `pdf_lines`。PDF 版的要求：
  - 周总结：最多 5 行，每行一个主要案件，一行内说完"做成了什么 / 推进到哪"；其余合成「その他」一行。
  - 日总结：1 行，说当天最主要的成果；同一天两三件事并列时用顿号连接，仍是一行。
  - 只为读得清楚而压缩，不新增网页版没有的事实。
- PDF 版式按 `pdf_text` 排：概要每行一个块；日別一天一行。`clamp` 兜底改为概要最多 6 行、每天最多 2 行。
- 手改：网页上改的是 `text`（`edited = 1`），同时把 `pdf_text` 清空。PDF 随即退回用 `text`（受 `clamp` 兜底）；下次本机生成时，对手改过且 `pdf_text` 为空的条目，只依据手改后的 `text` 生成 PDF 版，不动 `text`。PDF 版暂不提供网页上的单独编辑。
- 接口：`digest-inputs` 的每一条多返回 `pdf_missing`（手改过且 `pdf_text` 为空）；`PUT …/generated` 的 body 加 `pdf_text`、`pdf_zh`、`pdf_en`，并接受 `{ pdf_only: true }` 模式（只写 PDF 版，允许 `edited = 1` 的条目）。

### 2.8 PDF 排版修正（C8，S3 线上核对）

用户下载 W41 ja PDF 后指出四个问题，全部在 PDF 的生成逻辑里修，界面不受影响：

1. **下半页太空**：`__fit()` 增加"放大"方向。内容高度不足可用高度的 85% 时，按 `grow1…grow3` 逐级放大正文字号与行距（`--s` 1.08 / 1.16 / 1.24，`--lh` 同步），直到接近填满或到最后一级；超出时仍按原来的 `fit1…clamp` 缩小。两个方向互斥：先判断是否超出，超出只缩不放。`pdf-check.mjs` 加一个"内容很少"的 fixture，期望用到 `grow` 且不超出。
2. **文字被省略**：PDF 里不再用单行省略。案件名、依頼元、日总结都允许换行（依頼元列最多 2 行）；只有走到最后的 `clamp` 兜底时才截断。日总结本身不再被生成器截断（§2.2 撤掉了 30 字上限，PDF 用 §2.6 的 `pdf_text`）。
3. **字体发虚**：原因是 Google Fonts 给现代浏览器的 Noto Serif / Sans JP、SC 是可变字体，Chromium 打印时把它们嵌成 Type 3，部分阅读器里显得发虚（Shippori Mincho 是静态字体，嵌成 CID TrueType，正常）。本机验证（2026-10-08）：用旧浏览器 UA 请求 Google Fonts 的 CSS，返回的是静态实例，嵌入后是 CID TrueType。做法：Worker 在渲染前用旧 UA 请求一次 `css2?…&text=<本页用到的字符>`（只含本页字形的小子集），把 `<link>` 换成内联 `<style>`（字体文件仍由浏览器按 CSS 里的地址下载，Worker 不做 base64，CPU 开销只有一次 fetch 和字符串替换）。请求失败时保留原 `<link>`（退回可变字体，不影响出 PDF）。`pdf-check.mjs` 断言所有字体都不是 Type 3。
4. **中英混排拥挤**：生成 HTML 时，在汉字 / 假名与半角字母、数字之间插入一个细空格（U+2009 THIN SPACE），只作用于显示文字，不改数据。纯函数 `spaceMixed(text)`，测试覆盖：中日文与英文、数字、版本号（`v2.3`）、括号与标点相邻（标点旁不加）。

### 2.7 平实的说法（C7）

适用于所有生成的总结：周 / 日总结的网页版与 PDF 版，以及 harvest 的 session 摘要（`src/worklog/harvest/summarize.py` 的提示词）。提示词统一加入：

- 用日常说法写结果和进展，读者是不懂技术的人（如人事、管理岗；仅作理解难度的参照）。
- 不用技术术语和缩写解释不了的词：库名、命令、文件名、函数名、"重构 / 部署 / 调试 / 迁移 / 优化"之类的工程动词，换成"做好了 / 改好了 / 修好了 / 整理了 / 上线了"这类说法。案件名、人名、产品名照原样保留（这是专有名词，不算术语）。
- 不要 AI 腔：不用"成功地 / 顺利地 / 全面地 / 进一步 / 赋能 / 助力 / 不仅…而且…"之类的套话，不加总结性的空话和形容词，直接说事实。
- 有数字就用数字（完成了 11/22、做好了 3 个画面），没有就不编。

session 摘要只改提示词，往后新采集的生效；已有的 session 摘要不重写（它们只是总结的输入）。session 摘要的 30 字上限保留（时间线一行显示，用户此前选定）。

规则 A 抽检（§2.5）的判定项加一条：外行能否读懂（无技术术语、无 AI 套话）；并单独抽 5 条 PDF 版核对"没有新增事实、读得清楚"。

### 2.5 规则 A 抽检

改写率远超 50%：本机重写完成后，抽 N = 10 条日总结 + 3 条周总结（不同周、不同案件数），把每条和它的完整输入并排导出，交独立 reviewer（不同 subagent_type）判定四项：没有编造事实；当天 / 本周最主要的进展都在；没有无用信息（步骤、工具名、复述）；与计划目标的对照正确。结果写 `evidence/s2c_audit.md`，汇总进 `audit_matrix.md`；不合格的按规则 B 归档，改提示词后重跑受影响的周。

## 4. 风险

| 风险 | 应对 |
|---|---|
| 本机生成期间有人在网页上手改 | PUT 遇到 `edited` 返回 409，不覆盖 |
| 生成到一半输入变了（harvest 刚上报新 session） | 指纹不符 409 `stale`，下次再跑 |
| 开关关着时本周新的一天没有总结 | 开发阶段接受；页面显示「—」，跑一次本机工具补上 |
| `claude -p` 输出不是合法 JSON | 记失败、跳过该条，打印出来 |
| 折行后周报页变高 | 预期内；列宽不变，只增行高 |
