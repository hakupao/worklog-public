# worklog 使用说明

> 这一页是写给「未来的自己」看的：每天要做哪几步、命令忘了怎么查、出了问题从哪里看、新电脑怎么装。开发者视角的内容在仓库 README 和 `docs/` 里，不在这里。

网址：<https://worklog.example.com>（Cloudflare Access 登录）。新界面的首页是 [此刻](#/v2/now)，各页地址都以 `#/v2/` 开头，直接打开网址就进新界面。旧版界面已删除；旧地址（`#/dashboard`、`#/tasks/…`、`#/timeline/…`、`#/report/…` 等书签）会自动跳到对应的新页面。

## 新界面一览

**底部 Dock**：七个页面键（此刻 / 时间线 / 案件 / 计划 / 週報 / 统计 / 说明），界面语言（中文 / 日本語 / EN），「表 · 里」切换，设置，最右边琥珀色的 **补记**（任何页面都能直接写一条今天的补记）。界面语言只换界面文字，案件名、摘要等数据保持原文。

**顶栏**：当前页名、日期、每台机器上次收集的时间（Mac 显示为 MAC，Win11 显示为 WIN；今天的只写时刻，更早的带日期），右边是时钟。

**表 / 里**：里世界是默认的深色点阵信息牌；表世界是给别人看时用的浅色排版，骨架相同。表世界可以在设置里隐藏模块（默认隐藏此刻页的「AI 费用」、「统计 · AI 费用」和「统计 · 周复盘」），被隐藏的模块直接不显示，一栏全被隐藏就整栏收起；里世界始终全部显示。

**快捷键**（光标在输入框里时不生效）：

- `W`：切换表世界 / 里世界。
- `Q`：眯眼，整页模糊，用来检查最重要的东西是不是一眼能看到；再按一次恢复。

几条通用规则：

- 案件在牌面上显示成「线路代号」：案件 ID `T20260918-01` 写成 `0918-01`，每个案件有自己的线路颜色。鼠标停在一个案件上，页面上同一案件的其他地方一起亮起。
- 在时间线、案件、计划里点一行（週報是点日別作業的格子）会从右边滑出玻璃抽屉，在里面查看和修改；按 Esc 或点抽屉外面关闭。这几页打开的周、日期、筛选和抽屉都写在地址里，刷新或把地址发给自己都会回到同一处。此刻的行不开抽屉（行里的键是跳转链接），统计页的行本身就是跳转链接；统计页的区间也写在地址里，周复盘选中的周不写。
- **润色**：你手动输入的文字（计划、今日安排的标题和具体要求、案件名和考え方、补记、手改的会话摘要、周报手改格子和手改的概要）保存后十几秒内会被改写成简洁的工作用语，三种语言都按改写后的意思显示；原意、名称、数字不会改。抽屉里字段后面的「润」展开可看到原文，按「还原」后这段原文按原样显示、不再润色（标记变成「原」，可「恢复润色」）；以后改成新的文字会再次润色。命令行 `wl ls` 显示的是原文。
- 说明页（就是这一页）的正文只有中文；新界面里左侧的章节键可以跳到各节。

## 此刻

[此刻](#/v2/now) 是新界面的首页，一屏看当下：

- **运行中**：最近一次收集时还在进行的会话（最多 3 条）：最后一段活跃区间的开始时刻、线路代号、案件名、机器、这段区间已持续多久。会话最后一次活动距那台机器最后一次收集不超过 10 分钟就算运行中（可在设置里改）；那台机器上次收集已超过 90 分钟时，它的会话都不算运行中（收集停了，牌面不再断言）。harvest 在 Mac 上每 15 分钟、在 Win11 上每小时跑一次，所以这里反映的是上次收集时的状态。
- **下一步**：按预判规则挑出的最多 3 条建议，标题后面是当前模式（早上排今日 / 专注中 / 周五 · 週報 / 收工检查），标题右边是依据（时刻、运行中几个、今日安排完成几条、未关联几个）。每条右边的键直接跳到要处理的地方；鼠标停在一条上会显示原因。
- **今日安排**：完成 x/y 和各条目：灯绿色 = 完成、琥珀色 = 部分完成、不亮 = 未完成，后面是今天花在所挂案件上的时间和 AI 写的进度。还没开始今天时显示计划里有几条可以带入。
- **运行情报**（右上）：有未关联类的提醒时变红，显示「【延误】」、原因和「关联」键；没有就是「运行正常」和各机器的收集时间。
- **AI 费用**（右侧）：今天涉及的会话的等价费用，以及本周累计（跨日会话按整段计入）。
- **今天的运行图**（左栏场景图下）：每台机器一排，时间轴拉满轨道宽度（点距固定，1 点约 4 分钟，随窗口宽度变），鼠标停在点上看是哪个会话。

### 预判下一步

「下一步」由 10 条规则产生。每条规则属于一个模式，只在该模式的时间窗里参与；「全天」的规则随时参与。默认的模式时间窗：

- 早上：周一到周五 06:00–11:00
- 专注：周一到周五 11:00–18:00
- 週報：周五 15:00–24:00
- 收工：周一到周五 18:00–24:00

时间窗可以重叠，「下一步」标题显示开始得最晚的那个。每条命中的建议得分 = 规则权重 × 紧急度（例如未关联的分钟越多越紧急），同一个对象只留得分最高的一条，取前 3 条。默认规则（括号里是默认模式，从上到下权重递减）：

1. 昨天未关联（早上）：上一个工作日还有未关联的会话，合计不少于 5 分钟。
2. 结束后未关联（全天）：今天的会话结束超过 30 分钟仍未关联（当天合计不足 5 分钟的不算）。
3. 两周内未关联（全天）：本周或上周、今天以前还有未关联的会话。
4. 今日安排未动（专注）：今日安排里挂了案件的条目，今天还没有任何会话。
5. 计划未排进今日（早上）：每日 / 本周计划条目今天还没排进今日安排。
6. 週報未下载（週報）：本周週報还没下载过。
7. AI 判定待确认（收工）：今日安排里 AI 判定过的条目还没手动确认。
8. 等回复（早上）：案件最近 3 天里最后一个会话的摘要里有「確認待ち」「待ち」「等待」「waiting」之类的词。
9. 上周遗留（专注）：本周档的计划条目是上周遗留下来的。
10. 下周没有计划（週報）：「本周」和「近期」档都没有进行中的条目。

前三条（未关联类）命中时也会让运行情报变红。每条规则都可以在 [设置](#/v2/settings) 里关掉、换模式、改参数、调整先后。

## 时间线

[时间线](#/v2/timeline) 看一周：

- 顶部：◀ ▶ 翻周（不在本周时多一个「本周」键），本周合计工时和会话数，AI 费用；有未关联的会话时出现红灯的「未关联 N 件」键，有隐藏的会话时出现「已隐藏 N」键。
- 本周运行图：周一到周五各一条日带（周末有工作时也显示），1 点 = 5 分钟，跨日会话按当日部分计入。点日带选这一天，点某个点直接打开那个会话；鼠标停在下方的线路图例上，突出这条线路。
- 下面列出选中那天的会话和补记：时间、线路、案件 / 摘要、机器、时长、轮数、费用。还没关联的会话线路一栏是 `--`，行末写着「关联」。鼠标停在一行上显示案件、时间、机器、时长、费用和完整摘要。右上 **＋ 补记** 给这一天写补记。
- **未关联筛选**：点「未关联 N 件」（或打开 [未关联筛选](#/v2/timeline?unlinked=1)），列表换成所有周还没关联的会话，时长最长的在前，再点一次回到按日查看。「已隐藏 N」打开后，被隐藏的会话也列出来，可以恢复。

点一个会话打开抽屉：

- **关联案件**：没关联时会提示不关联的话週報少记多少分钟；同一目录的其他会话关联过的案件列成「推荐」，点一下就关联。「选择案件…」列出进行中和保留的案件（加上当前已关联的那个），也可以选「未关联」，或选「＋ 新建案件…」当场建一个；已关联的可以「更改」或「解除关联」。
- **摘要**：自动摘要不准就点文字直接改，「↺ 恢复自动摘要」回到自动值。
- **本日工时**：点数字改（小时）。跨日的会话显示这一天的份额和「整段」；「↺ 恢复自动工时」回到采集值。
- 活跃区间、机器、目录、对话轮数、AI 费用与 token。目录旁边可以「只看此目录」（筛选整页），或「隐藏本周此目录下的全部 N 条」（确认后批量隐藏，可在「已隐藏」里找回）。
- 最下面「隐藏此会话」：纯闲聊或无关的会话不计工时；隐藏后可以撤销。

点一条补记打开抽屉，可以改内容、关联的案件（同样只列进行中和保留的案件）、用时，或删除。

## 案件

[案件](#/v2/tasks) 一行一个案件：状态、线路代号、受領日、案件名、依頼元、本周每日的工时条、本周工时、累计工时、最近一次会话的日期（正在运行时写「运行中」），按受領日倒序。

- 顶部的状态键：进行中 / 保留 / 完了，可以多选，默认只看进行中和保留；「全部」一次全选。
- 右上 **＋ 新建案件**：填依頼元、案件名，项目可留空；建好后直接打开它的抽屉。

点一行打开抽屉：

- 案件名、依頼元（可以有好几个，回车追加，× 删除）、项目、受領日都可以点了直接改；完了日在标为完了时记下。
- 状态键在进行中 / 保留 / 完了之间切换（「标为完了」「保留」「改回进行中」）。
- **手动工时**：不填就按会话自动计算；填了就用它覆盖自动合计，「↺ 恢复自动工时」清掉。
- 合计工时、本周工时、会话数、AI 费用与 token。
- **考え方**：週報的备考列出的就是它，点了直接写。
- **成果物**：分两部分。
  - 手动添加的：在输入框里写文件名或路径，回车添加，× 删除。
  - 自动关联的：系统从关联会话里自动带出的成果物，排在手动项后面，有两种来源：
    - 会话写过的文档。代码、数据、配置不算；明显的过程文件（计划、证据、评审、prompt、scratch 等目录和文件）由规则直接排除；剩下拿不准的，由每台机器在 harvest 结束后让本机的 `claude` 判断，拿不准时收入。
    - 会话发布的 Claude Artifact 页面，全部收入，显示标题，打开就是页面。
  - 每条自动项右边有一个来源标记：规则 / AI 判定 / 已确认 / Artifact / 待判定。鼠标停在标记上可以看判定理由。
  - × 把一条移到下面的「已排除（n）」里；在那里点 ＋ 可以收回。你点过的判定以后不会被覆盖。
  - 标题旁的数字只算收入的，不算待判定的。
- 关联的会话和备注：会话可以在时间线打开，也可以在这里单独「解除关联」或隐藏。
- 最下面「危险操作」：删除案件。还关联着会话或备注时按钮不能用；还被计划或今日安排引用时删除会被拒绝并提示。都要先解除关联。

## 计划

[计划](#/v2/plan) 上半部分是某一天的今日安排，右边是 AI 对账，下面是四档计划的时刻表。

**今日安排**：‹ › 切换日期，不在今天时多一个「回到今天」。点「开始今天」（别的日期是「开始这天」）会带入有效的每日条目，加上上一份安排里没做完的条目（连同当时写的具体要求；已不再生效的每日条目不带入）。之后可以「＋ 临时加一条」，或者用「从计划添加…」把任意一条计划加进来。每行显示判定（完成 / 部分 / 未做）、条目、所挂案件，以及判定来自 AI、手动还是未对账；行上会轮流显示今天在所挂案件上的时间和会话摘要、具体要求、AI 写的进度。

点一行打开抽屉：改条目内容；「判定」选 完成 / 部分 / 未做 手动覆盖，选「自动」回到 AI 的结果；增减案件（今日条目继承所属计划的案件，也可以单独改；没挂案件 AI 就无从对账）；写「具体要求」，例如「和 agent 至少两轮，把导入模块的 DB 写入做完」；↑ ↓ 调顺序；看 AI 判定和依据（依据里的会话可以在时间线打开）；删除这条。完成今日条目不会改动案件。

**AI 对账**（右栏）：每小时一次，在 `wl harvest` 结束后（Mac 的分层收集在每小时的第一轮），模型对照当天的会话（摘要、案件、agent、轮数、时长）和补记，给每条标「完成 / 部分 / 未做」，并写上进度和依据。右栏显示上次对账的时间和机器、完成了几条，以及这周每天完成了几条。内容没变就不会重复调用模型；跨零点的会话只算当天那部分，轮数是估算。想立刻刷新就跑 `bin/wl plan judge`（强制重判，可加 `--date YYYY-MM-DD` 指定日期）。手动判定优先，之后的自动对账不会覆盖它。

AI 按「具体要求」判定，条目内容只当背景。AI 一旦判了完成，当天之后的对账不会再把它降回部分或未做（除非它引用的会话都已不在当天）。AI 误判成完成时，在抽屉里手动选「判定」；或者改条目内容、具体要求或所挂案件，这会清掉 AI 的判定，下一次对账重新判。

**时刻表**（下方）：每日、本周、近期、远期四档。每日是每天推进一点直到完成的事（挂了案件的，挂的案件全部完成以后自动不再生效，标「不在期」；可以设截止日，过了截止日同样不在期；也可以放例行事务）；本周里周已过还没完成的标「上周遗留」；远期的条目可以「转成案件」。「＋ 新增条目」选档位后添加。点一行打开抽屉：改内容、换档位、挂多个案件（「＋ 案件」追加，× 移除）、设截止日（每日档）、↑ ↓ 排序、标完成或放弃；上周遗留的可以「留在本周」或「下放近期」。「查看已完成 / 已放弃」列出关闭的条目，打开后可以恢复。

被计划或今日安排引用的案件不能删除。

## 週報

[週報](#/v2/report) 按表格的样子预览一周：

- 顶部：◀ ▶ 翻周（不在本周时多一个「本周」键），上次下载的时间，**导出语言**（中文 / 日本語 / EN，默认日本語），**↓ PDF** 和 **↓ xlsx**（跨周工作报告，打开面板选择起止周）。
- 本周有未关联的会话时，顶部提示「本周有 N 条会话未关联（M 分钟），不会计入任何案件」，「查看时间线 →」跳到那一周的未关联筛选。这些工时只进「未割当」，不进任何案件。
- 工作表键：サマリー / 案件一覧 / 日別作業 / 成果物 / 稼働，默认打开日別作業。日別作業每天按会话和补记逐条列出，带分钟数。成果物表先列手动添加的（日期为完了日），再列本周会话写过或发布过的自动成果物（日期为本周最后一次写入的那天）；对自动行的手改会跟着那份成果物走，不会因为列表增减而错位。
- **日別作業**：点任意格子打开抽屉，改工数和作業内容，下面列出这一格由哪些会话和补记汇总而来；「恢复自动值」回到计算值。
- 其他工作表：点格子直接改，改过的格子后面有 ✎，「↺ 恢复自动值」回到计算值。
- 改动保存在服务端，下周再打开还在。格子里的文字放不下时换行显示全文，不再省略。
- **本周概要** 与 日別作業 每天的 **当日概要**：按案件分行写这一周 / 这一天推进到哪（有计划目标时对照目标），零碎的事合成一行「■ その他」；用平实的说法，不写操作步骤和工具名。点文字直接改（可多行），改过的标「已手改」，之后不会被自动覆盖。输入变了还没重写的标「待更新」。
- 本周概要上的 **↻**：现在 API 生成关着（`DIGESTS_AUTO` = `off`），↻ 只把这条标成待更新，提示「已标记，下次本机生成时重写」；真正重写要跑一次本机生成（见「本机重写周报总结」）。
- **↓ PDF**：按导出语言生成一页 A4 的週報（不分模板），文件名 `<週>-<lang>.pdf`。内容是期間、氏名、概要、日別、案件；概要和日別用总结的 PDF 版（比网页版短），手改过的总结在补出 PDF 版之前用手改后的文字。PDF **不读**表格里手改的单元格。発行日是下载当天，氏名在 [设置](#/v2/settings) 里改。生成要几秒，按钮显示「生成中…」；20 秒内连点会提示「PDF 服务繁忙，请 N 秒后再试」，当天额度用完时提示明天再试。
- **编排**（↓ PDF 旁）：打开 `#/v2/report/<週>/pdf`，自己决定 PDF 里写哪些案件、什么顺序。
  - **每个案件三种状态**：**单列**（按你拖的顺序或 ↑↓ 出现在案件表和概要里）、**其他**（并入最后一行「その他」）、**隐藏**（不写进文字，但工时仍算进合计和その他）。单列最多 5 个；有「其他」时最多 5 个，没有「其他」时最多 6 个，多出来的自动折进「其他」。
  - **沿用上周**：第一次打开某周时，沿用最近一周的设置（最多往回 8 周），本周新出现的案件排在单列最后。
  - **即时预览**：表格和 PDF 版式随改动即时变化，不调用 PDF 服务。
  - **生成**：文字要点点 **生成**，由 Worker 调 Opus 一次写出日中英三语，约 20–40 秒；失败时只在开始后 50 秒内自动重试一次。每个案件的 ■ 开头和最后的「その他」行由服务端按规范的案件名写，模型只写正文。
  - **行数上限**：提示里的上限是 日 136 / 中 136 / 英 280 字符，检查阈值是 144 / 144 / 294。超出时服务端自动缩短：只保留整句，仍超出时「その他」改成只列名字（每个名字都列出）。
  - **手改**：生成后的文字可直接改。改了一种语言，另外两种用术语表和重写开头自动重译；保存会等重译做完（约 20 秒，期间显示「翻译中…」），重译失败时显示「翻译未完成」，可再试。生成进行中不能改文字。
  - **下载前提醒**：选择或当周数据改了但没重新生成（文字已过期）时，↓ PDF 会先提醒（编排页和週報页的 ↓ PDF 都会）：「先生成」打开编排页，「仍然下载」照旧下载。
  - 没编排过的周，↓ PDF 与以前完全一样。
  - 说明：Worker 上所有模型调用（含翻译）现在都用 `claude-opus-5-5`。
- **↓ xlsx**：导出内容为跨周报告，不限于当前所选周。打开面板后选择**起始周**、**结束周**和语言；语言的初始值取自顶部的导出语言（默认日本語），可在面板内更改。默认范围为最近 52 周（从有数据的第一周或 51 周前算起，取较晚者，到本周）。起始周晚于结束周时，面板禁用下载并说明原因（接口返回 400 `from after to`）；超过 52 周同样禁用（接口返回 400 `too many weeks`）；周或语言参数无效时接口返回 400 `invalid week` / `invalid lang`。文件名为 `<起始週>_<結束週>-<lang>.xlsx`。各表名称、表头及说明采用正式书面语，提供日、中、英三种语言。共五个工作表：
  - **表紙・概要**：标题、期间、用途和各表说明，其后为 KPI 表（附定义）和四张图表。
  - **当週業務内容**：范围内最后一周的本周概要和任务表，列有当週作業時間 / 通算作業時間 / 状態 / 成果物；该周没有一句话时，概要处显示主要案件名。
  - **週次一覧**：每周一行，含该周的一句话；没有一句话时显示主要案件名。
  - **案件一覧**：范围内涉及的案件。
  - **データ**：图表的底表。
  报告不包含手工修改的单元格（同 PDF）。下载会把范围内的每一周都记为「已下载」；范围包含本报告周时，[此刻](#/v2/now) 的「未下载」提示随之消失。
- **一句话**：本周概要下方多一行一句话，用于週次一覧中该周的说明。生成总结时一并写出；仅当该周已有总结行时才能编辑，直接编辑即可（留空 = 清除，最多 120 字；只有手工编辑的一句话才会润色，可用「润」查看原文、「还原」）。手改本周概要正文后，AI 写的一句话失效，下次本机生成时按新正文重写；手工编辑过的一句话保留。**↻** 将正文和一句话一并交由本机重新生成。

## 统计

[统计](#/v2/stats) 看一段时间的总体情况：

- **区间**：今天 / 本周 / 本月 / 近 4 周（默认）/ 近 3 个月，◀ ▶ 往前翻一段、翻回来（不能翻到今天之后）：本周 / 本月翻到上一整周（周一到周日）/ 上一整月，今天 / 近 4 周 / 近 3 个月按自身长度往前翻。
- **指标条**：总工时、活跃天数、会话、完了案件、Token、等价费用，每项都有与上一段相同长度时期的对比。费用后面的 `*` 表示部分会话未定价。
- **提示**：未关联的会话、完了但没有成果物的案件、某台机器超过 3 天没有新会话、open 案件超过 14 天没有会话或补记、摘要用 fallback 版本、深夜（22–5 时）/ 周末工作占比超过 20%、单个会话的等价费用超过 $100、单个会话超过 80% 的 token 花在子 agent 上（且该会话总 token 超过 10M），这些情形都会一行一条提示，右边的键跳到时间线或案件去处理。
- **时间花在哪**：按案件的账本（前 10 个案件的工时、费用、$/h；$/h 只按有 token 数据的会话时长算，补记不计，有未定价的会话时带 `*`）、未关联的合计，以及每周的工时条（被区间截断的周只算区间内的日子，标签写裁剪后的日期；鼠标停上去看各项目的小时）。
- **按依頼元**：每个依頼元的时间、占总工时的比例、Token 和费用。多依頼元的案件按人数平分，未挂案件的算「未关联」。
- **产出**：完了案件数、平均交付周期、成果物数，完了的案件列表，以及工时估算偏差（手动工时 / 实际）。
- **工作节奏**：平均开始 / 结束时刻、深夜（22–5 时）与周末的占比，每日工时柱（8h、24h 两条参考线；单日超过 24h 是并行会话重叠计时），一周 7×24 的时段分布，单次会话时长的分布。
- **AI 使用效率**：子 agent 占比、缓存命中率、每小时费用，按模型的 token，Claude Code / Codex 各自的会话数和工时，费用最高的 5 个案件，最贵的 5 个会话（点一下在时间线打开）。
- **每周复盘**：一排周键（W40 W39 …，默认最新一周），下面是那一周的 AI 复盘。一周结束后的第一次 `wl harvest` 会自动生成上一周（周一到周日，东京时间）的复盘，先写入的那台机器为准。复盘由 `summarize_model` 生成，仅使用那一周的统计数据和上周的复盘文字。如果生成时那一周的数据不完整（例如另一台机器还没 harvest），用 `bin/wl review --week 2026-W39 --force` 重新生成。也可以手动运行 `bin/wl review [--week 2026-W39] [--force]` 查看或重新生成。

表世界默认隐藏费用（指标条的等价费用、AI 使用效率整栏、账本的费用列、依頼元表的费用列，以及会话等价费用超过 $100 的那条提示），要给别人看费用就在设置里勾上「统计 · AI 费用」。每周复盘的正文里也常写到费用金额，表世界默认整段不显示，要显示就在设置里勾上「统计 · 周复盘」（与「统计 · AI 费用」各管各的）。

## 每天的固定动作

### 早上（上班后 5 分钟）

1. 打开 **此刻**，先看「下一步」和运行情报：昨天还有未关联的会话时，点「关联」进时间线的未关联筛选，逐个打开，挂到案件上（或点「推荐」）；纯闲聊或无关的会话点「隐藏此会话」（不计工时）。以前几周积压下来的，也都在未关联筛选里，按时长从长到短排。
2. 打开 **计划**，点「开始今天」，给每条写「具体要求」，需要的话从计划里再加几条。
3. 切到 **案件** 页，默认只显示进行中 / 保留：今天要做的案件已经在列表里就不用动；新来的依頼点右上 **＋ 新建案件**（填 依頼元、案件名，项目可留空）。
4. 关掉网页去干活。harvest 在后台自动跑（Mac 每 15 分钟、Win11 每小时，不弹窗），不用手动收集；等不及可以手动跑一次 `bin/wl harvest`。

### 收工前（下班前 5 分钟）

1. **时间线** 看今天：把「未关联」的会话挂到案件上；自动摘要不准就在抽屉里点摘要直接改，工时不对就改「本日工时」。
2. 有值得写进週報 备考 的想法，打开对应案件的抽屉在 **考え方** 里补一句；或者在时间线当天点 **＋ 补记**（也可以用 Dock 上的 **补记**；选案件、写内容、可填用时）。
3. 做完的案件：在案件抽屉里点 **标为完了**，看一眼 成果物：自动关联的不对就 ×，缺的手动加上（文件名或路径）。
4. 打开 **计划**，看 AI 判定对不对，不对就在抽屉里手动改「判定」。

### 周五收工前（週報）

1. 打开 **週報** 页，先看顶部有没有「本周有 N 条会话未关联」的提醒。有就点「查看时间线 →」挂完再来，否则那些工时不会进任何案件。
2. 各工作表看一遍。哪个格子想改就直接点格子改，改动会保存在服务端（下周再打开还在）；「恢复自动值」回到计算值。
3. 看一遍本周概要和每天的当日概要；标「待更新」的先在终端跑一次 `node scripts/digests-local.mjs` 再刷新页面。
4. 如需跨周报告，点击 **↓ xlsx**，在面板中选择起止周和语言，导出 `<起始週>_<結束週>-<lang>.xlsx`（最多 52 周）；如需一页纸的版本，选择导出语言后点击 **↓ PDF**，得到 `<週>-<lang>.pdf`。

## 起票 / 补记的三种写法

三种写的是同一个服务端，用哪种看当时手在哪里。

命令示例都在仓库根目录里跑：Mac 上是 `bin/wl`，Win11 上是 `bin\wl.exe`。在别的目录就写二进制的绝对路径（`<仓库>/bin/wl …`），它会从自己所在的目录往上找到仓库的 `config.toml`；或者在 Claude Code 里用 `/wl` 技能。正文里简写成 `wl …`。

| 想做的事 | 网页 | 终端 | Claude Code 里说一句（/wl 技能） |
|---|---|---|---|
| 新案件 | 案件页 ＋ 新建案件 | `bin/wl new 田中 帳票修正 --project order` | 「田中さんから帳票修正の依頼が来た、プロジェクトは order」 |
| 补一条进度 | Dock 补记 / 时间线 ＋ 补记 / 案件抽屉 考え方 | `bin/wl note T20260918-01 "原因は文字コード" --minutes 15` | 「さっきの帳票修正、原因は文字コードだった。15 分かかった」 |
| 和案件无关的备忘 | 补记，案件选「未关联」 | `bin/wl note - "社内勉強会"` | 「案件と関係ないメモ：社内勉強会」 |
| 完了 | 案件抽屉 标为完了 | `bin/wl done T20260918-01 --deliverable output/a.xlsx --hours 2` | 「帳票修正、終わった。成果物は output/a.xlsx、2 時間」 |
| 保留 | 案件抽屉 保留 | `bin/wl hold T20260918-01` | 「帳票修正は保留にして」 |
| 看案件列表 | 案件页 | `bin/wl ls`（加 `--all` 含完了） | 「今の案件一覧」 |
| 手动收集 session | 无 | `bin/wl harvest` | 「harvest して」 |

几条只有 CLI 才有的细节：

- `wl note <案件ID>` 除了存一条 note，还会把同一句追加到案件的 考え方（週報的 备考 列出的就是它）。`wl note -` 不碰 考え方。
- `wl note` 发不出去会先存到 `~/.worklog/outbox/`，下次 harvest 自动重发，所以**别重复敲同一条**。`wl new` / `wl done` / `wl hold` 失败就是没写进去，退出码 1，看提示再来一次。
- 删除案件只能在网页上：案件抽屉最下面的「危险操作」。有关联会话、补记或计划的案件删不掉，会提示先去解除关联；这是故意的。
- 依頼元 的叫法（「田中」→「田中さん（営業部）」）在仓库 `config.toml` 的 `[requesters]` 里配；`[projects]` 里配「目录 → 项目名」，harvest 靠它自动把 session 挂到案件上，配法见「让 session 自动挂到案件」一节。
- 时间线和案件抽屉里的 token 用量与 AI 费用（按 `config.toml` 的 `[pricing]` 单价估算；Codex 按 OpenAI 短上下文单价，长上下文部分会偏低）由 harvest 一并采集。更新之前采集的 session、或改了单价之后，跑一次 `bin/wl harvest --refresh-meta` 重算全部 session 的 token、写过的文件、发布的 Artifact 与活跃区间，不重新生成摘要（`--files-only` 是它的旧名，效果相同）。
- 一个跨过午夜（东京时间）还在用的 session，它的工时按实际活跃时段拆到各天：时间线上它会出现在每一天下面，按当天的份额计时，抽屉里的「本日工时」旁边写着整段的工时；统计与週報的每日数字同样按份额算。手改过的工时按同样比例拆。

## 本机重写周报总结

服务端用 API 自动写总结的开关（`DIGESTS_AUTO`）目前是关的，周报页每一天、每周的总结由本机用 `claude -p` 生成再写回服务端（日语原文，同时带中文、英文译文和 PDF 用的短版）。在仓库根目录运行：

```bash
node scripts/digests-local.mjs                      # 默认：本报告周和上一周，只处理还没生成或输入已变的
node scripts/digests-local.mjs --from 2026-W38 --to 2026-W41
node scripts/digests-local.mjs --oneliners --from 2026-W01 --to 2026-W41 --save oneliners.json   # 一次性补充历史数据（一句话）：只生成到文件，供审阅
node scripts/digests-local.mjs --oneliners --from 2026-W01 --to 2026-W41 --load oneliners.json   # 审阅后写回文件中的条目
node scripts/digests-local.mjs --dry-run            # 只列出每周要处理的天，不调 claude，不写任何东西
node scripts/digests-local.mjs --all                # 已是最新的也全部重写（手改过的不动）
```

- 现在的写法：每个有进展的案件一行，对照计划目标写推进到哪、卡在哪；零碎的事合成「■ その他」一行。输入包括当周的工时、案件信息、计划目标、今日安排的判定、上周的周总结；其中工时、案件状态、目标的完成情况按这一周结束时算，案件名、備考、计划文字用的是当前值。中文、英文译文里的案件名用案件表里的译名。周总结的 PDF 版漏掉「■ その他」行时，工具会把网页版那一行补进去。
- 日常运行同时写每个重新生成的周的一句话；另外，默认范围（本报告周和上一周，或 `--from` 起）内有总结正文、但没有一句话的周（含从未有过的，以及手改正文使其失效的）也会补充生成，每周多一次调用。
- 一次性补充历史数据分两步，`--save` 与 `--load` 互斥，且都必须带 `--oneliners` 和 `--from`：
  1. `node scripts/digests-local.mjs --oneliners --from <W> [--to <W>] --save <file>`：只生成到文件，不写服务端，供审阅（抽检）。
  2. `node scripts/digests-local.mjs --oneliners --from <W> [--to <W>] --load <file>`：不调 claude，只写回文件中范围内（`--to` 默认为本报告周）的条目，范围外的计数后忽略；全部被忽略或有写入失败时退出码为 1，404 / 409 算跳过。
  - 写回时各值先去除首尾空白；仅当该周正文仍与生成时的 `source_text` 一致、一句话为空且未被手工编辑时，服务端才接受。
  - `--oneliners --dry-run` 只列出各周的 `oneliner_missing`，不调 claude，也不生成文件。
- 周报页上的 ↻ 只做标记，不会自己重写；标记过的条目下次跑本工具时（不带 `--all` 也会）被重写。
- 手改过的总结不会被覆盖；只有它的 PDF 短版缺失时才会补充生成。写回时若这一天又有新 session 上报或刚被手改，服务端会拒绝（日志里显示 409 stale / edited，算跳过，不算失败）。
- 其他参数：`--model`（默认 `opus`）、`--concurrency`（默认 3）、`--claude <命令>`（默认 `claude`）。
- 默认只处理本报告周和上一周（与 cron 开启时的范围相同）；更早的周必须显式给 `--from`。已经交出去的週報不会因为之后改了備考 / 案件名而被默认重写。
- `--dry-run` 只读：从服务器读输入、列出每周要处理的天，不调 claude、不写回。不带 `--base` / `WORKLOG_API` 时它读的是正式环境。
- 服务器地址：`--base <url>` 优先，其次环境变量 `WORKLOG_API`，都没有时读 `config.toml` 的 `api_url`——也就是说**默认写的是正式环境**，本地试跑要给 `--base http://localhost:8787` 或设 `WORKLOG_API`。令牌读 `WORKLOG_TOKEN`，没有时读 `~/.worklog/credentials.toml`；有失败时退出码为 1。

## 15 分钟分层收集（Mac，`wl harvest --tiered`）

Mac 上 launchd 每小时的 0、15、30、45 分各跑一次 `bin/wl harvest --tiered`（plist 的 `ProgramArguments` 带 `--tiered`，`StartCalendarInterval` 是这四个分钟）。Win11 仍是每小时 0 分一次全量收集（`scripts/schtasks-harvest.ps1`，不带 `--tiered`）。

- **每 15 分钟**：发出 outbox、只读上次之后变过的日志、发心跳。没有日志变化的一轮不调用 `claude`，只有「读案件列表」和「心跳」两个请求。
- **摘要**：新会话马上摘要；进行中的会话最多每小时重新摘要一次，停下（最后一条消息过了 30 分钟）后再补一次最终摘要；中间几轮沿用上次的摘要，只更新数字。摘要失败（fallback）的会话按 1、2、4、8 小时、之后每 24 小时重试，日志不动也会重试。
- **其他工作按时段**，每个时段只做一次：今天的计划对账、成果物判定每小时一次；昨天的计划对账每天 05:00 之后一次；上周复盘每周一次（没成功时每小时最多再试一次）。电脑睡眠醒来后，错过的时段各补一次，不逐个补。`, unassigned=N` 也只在每小时的第一轮出现。
- **手动 `wl harvest`**（不带 `--tiered`）照旧是全量收集：读全部日志、所有工作都做一遍。「收集一下」时用它。
- **注意 `--since`**：手动跑 `wl harvest --tiered --since 60` 这类超过 14 天的窗口时，9/30 之前的旧书签（没有指纹）会被当成旧的 fallback 领养（R7），每个会话重新摘要一次。
- **多出来的输出**：stderr 多一行 `tiers: due=15m[,1h][,day][,week] parsed=… new=… bootstrap=… reused=… refreshed=… failed=… adopted=… jobs=…`，每个会话的决定写在 `~/.worklog/tiers.jsonl`（只有规则和指纹，没有摘要原文；每天保留最近 8 天）。分层用的缓存在 `~/.worklog/collector_state.json`。
- **两个 harvest 同时跑**：后一个看到 `~/.worklog/harvest.lock` 就退出，提示 `another harvest is running`；定时任务退出码 0，手动运行退出码 2，过一会再跑即可。持锁进程已经不在、或锁超过 60 分钟时会自动接管。
- **昨天的计划在 05:00 之后又改了**：那天的最终自动对账已经做过，不会再自动重判。需要时手动跑 `wl plan judge --date YYYY-MM-DD`（例如 `wl plan judge --date 2026-10-20`）。

**回退到每小时全量收集**，按顺序做：

1. 停掉定时任务：`launchctl unload ~/Library/LaunchAgents/com.worklog.harvest.plist`。
2. 在仓库根目录跑一次 `go -C collector run ./tools/tiered-rollback ~/.worklog`，它打印 `reset=N`。全量模式不会再刷新日志已经不动的会话的摘要，所以这一步把摘要过时或是 fallback 的 N 个会话的书签（`harvest_state.json`）重置为 `{mtime: 0}`，其余书签和其他文件都不动。
3. 把 `~/Library/LaunchAgents/com.worklog.harvest.plist` 改回每小时一次的全量收集：`ProgramArguments` 去掉 `--tiered`（只剩 `bin/wl` 和 `harvest`），`StartCalendarInterval` 只留 `Minute` 为 0 的那一项，然后 `launchctl load`。下一次全量收集会把这 N 个会话重新摘要一次。

## 出问题时怎么办

| 现象 | 先看哪里 | 通常原因 / 处理 |
|---|---|---|
| 顶栏某台机器的收集时间停在很久以前、或没出现（超过 3 天没有新会话时，统计页会提示「<机器> 已 N 天以上没有新会话」） | 那台机器上手动跑 `bin/wl harvest`（Win11 是 `bin\wl.exe harvest`） | 定时任务没在跑：Mac 看 `launchctl list \| grep worklog` 和 `/tmp/worklog-harvest.err.log`；Win11 看 `%USERPROFILE%\.worklog\harvest.log` 的最后一行（没有新行、或是 `wl.exe` / cmd 的报错就是没跑成），和 `Get-ScheduledTaskInfo -TaskName WorklogHarvest` 的 `LastRunTime` 有没有前进。`LastTaskResult` 不要看：任务经 `conhost --headless` 启动，失败了它也是 0 |
| harvest 最后一行 `fallback=N`（N>0） | `claude -p "hi"` 能不能返回 | 摘要用的 `claude` 没登录或不在 PATH（launchd 的 PATH 要写全，见 plist 注释）。数据已经推送了，只是摘要是退化版，之后在时间线的抽屉里手改摘要即可 |
| harvest 最后一行 `parked=N` 或 `rejected=N` | `~/.worklog/outbox/`（rejected 在 `outbox/rejected/`） | parked：没发出去，下次自动重发，多半是网络或凭据；rejected：服务端拒收，不会重发，打开文件看内容是什么再决定在网页补 |
| harvest 退出码 2「api unreachable」 | `~/.worklog/credentials.toml` 三个键 | 读不到案件列表就整轮不采集（防止把所有 session 当未关联发出去）；凭据和 Mac 上的应完全一致 |
| 网页提示「登录已过期，请刷新页面」或打开是 Access 登录页 | 刷新 | Access 会话到期，重新登录一次 |
| 网页保存时提示「这条记录已在别处被修改，已刷新为最新内容」 | 页面已经是最新的 | 另一处（CLI 或另一个标签页）刚改过同一条，看一眼再保存一次 |
| 週報数字不对 | 週報页顶部的未关联提醒；时间线的「已隐藏」 | 未关联的只进「未割当」，不进任何案件；隐藏的不计入；案件抽屉里可以填「手动工时」覆盖自动合计 |
| 週報某格改错了 | 点那个格子 | 「恢复自动值」 |
| `wl note` 提示「備考 was not written」 | 案件抽屉的 考え方 | note 已存，只是 考え方 没追加成功；去网页补一句，**别**重跑 `wl note`（会存两条） |

## 新机器怎么装

以 Win11 为例（Mac 把路径换成 `~/`，定时任务用 launchd）。

1. `git clone git@github.com:hakupao/worklog-public.git`，进目录放好 `wl`：
   - Win11：装好 `gh` 并登录（`gh auth status` 能通过），在仓库根目录跑 `powershell -ExecutionPolicy Bypass -File scripts\update-wl.ps1 -Tag <wl-vX.Y.Z> -Dest bin`（`-Tag` 填最新的 `wl-v…` Release）。它下载 Release、核对 SHA-256 后放到 `bin\wl.exe`；以后升级也跑这一条。
   - Mac：装 Go（版本见 `collector/go.mod`），跑 `make -C collector build`，产出 `bin/wl`。
2. 装 Claude Code 并登录（`claude -p "hi"` 能返回）。harvest 用它做摘要，没有也能跑但摘要全是 fallback。
3. 写 `%USERPROFILE%\.worklog\credentials.toml`（三个键和现有机器完全一样，用 1Password 之类传，别贴进聊天）：
   ```toml
   api_token = "..."
   access_client_id = "..."
   access_client_secret = "..."
   ```
4. 写 `%USERPROFILE%\.worklog\local.toml`：
   ```toml
   machine = "win11"
   ```
   机器名只写这里，**不要写进仓库里的 `config.toml`**（它是所有机器共用的）。
   这台机器上的项目目录要写进 `config.toml` 的 `[projects]`，配法见下一节。
5. 手动跑一次 `bin\wl.exe harvest`（Mac 是 `bin/wl harvest`），退出码 0、最后一行形如 `new=N updated=N parked=0 skipped=N fallback=0`（后面可能再跟 `, unassigned=N`），网页顶栏出现这台机器（名字以 win 开头的显示为 WIN）和刚才的收集时间。
6. 注册定时任务：Win11 在 PowerShell 里跑 `.\scripts\schtasks-harvest.ps1`（每小时 0 分一次全量的 `bin\wl.exe harvest`、无窗口，任务名 `WorklogHarvest`，输出追加到 `%USERPROFILE%\.worklog\harvest.log`；没有 `bin\wl.exe` 时报错、不注册；挪了仓库要重跑；旧的会弹窗的任务先 `Unregister-ScheduledTask` 掉）；Mac 先把 `scripts/com.worklog.harvest.plist` 里的占位路径改成本机的（`ProgramArguments` 里 `bin/wl` 的路径、能找到 `claude` 的 `PATH`（按 `which claude`）、`WORKLOG_ROOT`、`WorkingDirectory`），再复制到 `~/Library/LaunchAgents/` 后 `launchctl load`（每 15 分钟一次 `--tiered`，见上面「15 分钟分层收集」）。
7. 想在 Claude Code 里用 `/wl`：Mac 跑 `./scripts/install-skill.sh`（需要先有 `bin/wl`），Win11 在 PowerShell 里跑 `.\scripts\install-skill.ps1`（需要先有 `bin\wl.exe`）。脚本会把本机仓库路径填进技能并写到 `~/.claude/skills/wl/SKILL.md`（不要手动链接或复制 `skills/wl`，里面是带占位符的模板）。改了模板或挪了仓库就重跑一次。

详细的逐步核对清单（含每步期望输出）在 `docs/projects/web-service/evidence/checklists/win11-onboarding.md`。

## 让 session 自动挂到案件：配置 `[projects]`

harvest 收到一个 session 时，看它的工作目录决定挂到哪个案件：

- **目录配在 `[projects]` 里**：只在这个项目的 対応中 / 完了 案件里找受領日到完了日覆盖这个 session 的。正好 1 个就挂上；0 个或好几个就留「未关联」，不会去别的项目里猜。子目录也算命中，好几条都命中时取最长的那条。
- **目录没配**：在所有项目的案件里按时间找，正好 1 个才挂上。同时开着好几个案件时基本都会留「未关联」；只开着 1 个时，这段时间在无关目录里的 session 也会被挂到它上面。

所以每台机器上常用的项目目录都应该配上。不配也能用，只是要天天去时间线手动挂。

配法：

1. 打开仓库根目录的 `config.toml`，在 `[projects]` 里一行写一个「目录 = 项目名」。项目名要和案件的「项目」栏写得**完全一样**（大小写也算），否则等于没配。
2. Windows 路径用单引号括起来，反斜杠照原样写，不用转义；Windows 上路径大小写不影响匹配。用双引号的话反斜杠要写成 `\\`，写错一处整份 `config.toml` 都读不了，`wl` 所有命令（包括定时的 harvest）都会报错。Mac 和 Windows 的路径写在同一段里就行，每台机器只会匹配到自己的：
   ```toml
   [projects]
   "/Volumes/Data/Projects/LEDGER" = "LEDGER"
   'C:\Work\Acme\LEDGER' = "LEDGER"
   ```
3. 只配对应一个项目的目录。`C:\Work\Acme` 这种下面放着好几个项目的上层目录不要配，否则下面没单独配的目录都会算进同一个项目。
4. 在 Mac 上改，commit、push，其他机器 `git pull`（Win11 不需要 push 权限，Windows 路径也在 Mac 上加）。之后新收或有更新的 session 按新配置挂；已经收过、之后没再动的 session 不会重挂，要么去时间线手动挂，要么删掉 `~/.worklog/harvest_state.json` 再跑一次 `bin/wl harvest`，重扫最近 14 天。重扫会把这 14 天的 session 全部重新交给 `claude -p` 摘要，几十个 session 要等几分钟。平时不用担心开着不动的 Claude Code 窗口：它的日志文件虽然每小时都在变，但没有新对话就不会重新摘要。手动挂过的不会被覆盖。

## 几个约定

- 日期和周都按东京时间算（JST）。跨 0 点的 session 按实际活跃时段把工时拆到各天（见「起票 / 补记的三种写法」最后一条）。
- 案件 ID 形如 `T20260918-01`：受領日 + 当天序号，网页和 CLI 起票共用一套编号；新界面上显示成线路代号 `0918-01`。
- 每台机器的 harvest 进度在自己的 `~/.worklog/harvest_state.json` 里，互不影响；删掉它会从最近 14 天重新扫一遍（服务端按 session id 去重，不会重复计）。
- 服务端是唯一的数据源，本地不留副本。备份靠 Cloudflare D1 本身，真要导出就从週報页下载 xlsx。
