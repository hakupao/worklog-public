# wl スキル

このスキルは、ユーザーの自然言語での発言を `worklog` (`wl`) CLI のコマンドに変換し、実行するためのものです。作業中のセッションから離れずに、案件の起票・進捗メモ・完了報告・案件一覧の確認などができます。

## 基本方針

1. ユーザーの発言から、依頼元 (requester) / 案件名 (title) / プロジェクト (project) / 内容 (メモ・成果物・工数) を読み取ります。
2. 対応する `wl` サブコマンドと引数を組み立てます。実行するコマンドは常に以下の形にします（このリポジトリの外から実行する場合も動くよう、インストール時にこの機械のリポジトリの場所を埋め込み済みです。呼ぶのはリポジトリの `bin/wl` (Windows は `bin/wl.exe`) です）。

   ```
   "@ROOT@/bin/wl" <サブコマンド> [引数...]
   ```

3. **実行前に組み立てたコマンドをユーザーに提示してから** Bash で実行します。
4. 実行結果（標準出力・エラー）をユーザーに分かりやすく報告します。失敗した場合はエラー内容をそのまま伝え、勝手に別の解釈で再実行しません。

## 対応コマンド

`wl` のサブコマンドはこの 6 つだけです。

| ユーザーの意図 | コマンド |
|---|---|
| 新しい依頼が来た | `wl new <依頼元> <案件名> [--project P] [--received YYYY-MM-DD]` |
| 完了報告 | `wl done <task_id> [--deliverable PATH ...] [--hours H]` |
| 保留にする | `wl hold <task_id>` |
| 進捗・気づきのメモ | `wl note <task_id\|-> <本文> [--minutes M]` |
| 案件一覧を見る | `wl ls [--all]` |
| 作業ログを収集する | `wl harvest` |

- `task_id` が発言中に無ければ、直近の `wl ls` の結果や会話の文脈から推測してよいですが、確信が持てない場合はユーザーに確認してください。
- 依頼元の表記ゆれは `wl` 側（config.toml の `[requesters]`）で吸収されるため、そのままユーザーの言い方で渡して構いません。
- セッションの紐付け・紐付け解除と週報の作成・確認は Web で行います（config.toml の `api_url` が指すサーバーの Web 画面）。CLI には該当コマンドがないので、頼まれたら Web を案内してください。
- 案件の詳細（紐付いたセッション・メモ）も Web の案件ページで見られます。
- 案件の削除は Web の案件ページ（一番下の危険操作）だけです。関連する session / メモがあると拒否されるので、先に時間線で紐付けを外すよう案内してください。CLI に削除コマンドはありません。
- `wl note <task_id>` はメモを保存すると同時に、その案件の 備考 にも本文を追記します（週報の 備考 列に出ます）。案件を指定しない `wl note -` は 備考 を触りません。
- 「備考 was not written」と出たときは、メモ自体は保存できているので `wl note` を再実行せず、Web の案件ページで 備考 を補記するようユーザーに伝えてください。
- すべての書き込みは API に直接送られます。サーバーに届かなかった `wl note` は `~/.worklog/outbox/` に保存され、次回の `wl harvest` で再送されます（終了コード 0）。同じメモを二重に登録しないよう、失敗しても同じ `wl note` をそのまま再実行しないでください。
- 終了コードが 1 のときは書き込みが残っていません（`wl done` / `wl hold` は outbox にも積みません）。エラー文をそのままユーザーに伝えてください。

## 例

**例 1（日本語・新規起票）**

ユーザー: 「田中さんから帳票修正の依頼が来た。プロジェクトは order」

実行コマンド:
```
"@ROOT@/bin/wl" new 田中 帳票修正 --project order
```

**例 2（日本語・進捗メモ）**

ユーザー: 「さっきの帳票修正の件、原因は文字コードだった。15分くらいかかった」

実行コマンド（直前の `wl new` で発番された ID、例えば `T20260918-01` を使う）:
```
"@ROOT@/bin/wl" note T20260918-01 "原因は文字コードだった" --minutes 15
```

**例 3（中文・完了报告）**

用户:「T20260918-01 的活儿做完了，交付物是 output/a.xlsx，花了 2 小时」

执行命令:
```
"@ROOT@/bin/wl" done T20260918-01 --deliverable output/a.xlsx --hours 2
```
